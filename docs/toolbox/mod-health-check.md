# Mod 体检

“Mod 体检”用只读方式比对 `addonlist.txt` 与磁盘上的 VPK 文件，用来定位“装了却不生效”“开关记录对不上”这类问题。

入口：**设置 → 游戏配置 → Mod 体检**。

## 使用步骤

1. 按需勾选“深度扫描”。
   - 不勾选：只做文件名与条目比对，速度很快。
   - 勾选：逐个解析 VPK 目录，能发现损坏文件，但 Mod 多时明显更慢。
2. 点击“开始体检”。
3. 按严重程度从上往下处理结果（严重 → 警告 → 提示）。

## 检查结果说明

| 结果 | 严重程度 | 含义 | 建议 |
| --- | --- | --- | --- |
| 条目缺少文件 | 严重 | `addonlist.txt` 里记录了某个 Mod，但磁盘上已经找不到该文件 | 点击“清理失效条目”，或把文件放回原位置 |
| VPK 无法解析 | 严重 | VPK 文件损坏或被截断（仅深度扫描） | 用“VPK 完整性检测”尝试修复并另存 |
| 只剩 disabled 副本 | 警告 | 文件被移到了 `disabled` 目录，但开关记录仍是开启 | 从 `disabled` 移回，或关闭该条目 |
| 重复条目 | 警告 | 同一个 Mod 在 `addonlist.txt` 中出现多次 | 点击“清理重复条目” |
| 孤立的工坊信息 | 提示 | 存在 `xxx.meta` 但没有对应的 `xxx.vpk` | 可以安全删除该 `.meta` |
| 缺少工坊信息 | 提示 | `workshop` 目录里的 VPK 缺少同名 `.meta`（仅在开启“工坊信息存储”时提示） | 重新下载或更新一次该 Mod |
| 依赖未开启 | 警告 | 主 Mod 已开启，但它声明的依赖处于关闭状态 | 点击“启用缺失依赖”，或在“Mod 依赖”里单独启用 |
| 依赖缺失 | 警告 | 依赖声明指向的文件在磁盘上找不到 | 重新下载该依赖，或删除这条依赖声明 |
| 未写入开关记录 | 提示 | 磁盘上有 Mod，但没有写进 `addonlist.txt` | 用游戏内开关或管理器启用一次即可记录 |
| 缺少 addonlist.txt | 警告 | 游戏还没写过开关状态文件 | 先进一次游戏或手动创建 |

## 一键清理重复条目

体检发现“重复条目”后，“清理重复条目”按钮会变为可用。它会保留每条的第一个记录、删除后续重复项。

## 清理失效条目

体检发现“条目缺少文件”后，“清理失效条目”按钮会变为可用。它会删除那些在 `addons`、`workshop`、`disabled` 三处都找不到文件的条目。

注意：工坊 Mod 的文件被删除（例如暂时退订）时，条目也会被判为失效。清理后如果文件重新下载，游戏会按默认状态加载它，而不是沿用原来的开关。

两种清理都会在写盘前建立一份“体检修复前”备份，可在同页的“历史备份”里恢复。

## 导出体检报告

体检完成后可以：

- **复制报告**：把结果转成 Markdown 复制到剪贴板，适合直接贴到社区、群聊或 Issue 里求助。
- **保存报告**：写入配置目录的 `reports/` 文件夹（文件名形如 `mod-health-20260922-103000.md`），
  并自动打开文件所在位置。重复保存会自动加序号，不会覆盖旧报告。

报告按严重程度分节（严重 / 警告 / 提示），每条包含类型、对象和说明；
名称与说明里的竖线会被转义，保证表格在 Markdown 里正常显示。

## 注意事项

- 体检本身**只读**：不会修改 `addonlist.txt` 或任何 VPK 文件。
- 只有“清理重复条目”和“清理失效条目”会写文件；两者都只删除条目，不改变保留条目的开关与顺序。
- “未写入开关记录”只代表管理器无法判断状态，并不等于该 Mod 没有生效；
  Steam 订阅的工坊 Mod 在未记录时通常仍会被游戏加载。
