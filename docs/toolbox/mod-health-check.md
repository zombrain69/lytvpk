# Mod 体检

“Mod 体检”用只读方式比对 `addonlist.txt` 与磁盘上的 VPK 文件，用来定位“装了却不生效”“开关记录对不上”这类问题。

入口：**设置 → 游戏配置 → Mod 体检**。

## 使用步骤

1. 按需勾选“深度扫描”。
   - 不勾选：只做文件名与条目比对，速度很快。
   - 勾选：逐个解析 VPK 目录，能发现损坏文件，但 Mod 多时明显更慢。
2. 点击“开始体检”。
3. 按严重程度从上往下处理结果（严重 → 警告 → 提示）。

## 检查结果说明

| 结果 | 严重程度 | 含义 | 建议 |
| --- | --- | --- | --- |
| 条目缺少文件 | 严重 | `addonlist.txt` 里记录了某个 Mod，但磁盘上已经找不到该文件 | 点击“清理失效条目”，或把文件放回原位置 |
| VPK 无法解析 | 严重 | VPK 文件损坏或被截断（仅深度扫描） | 用“VPK 完整性检测”尝试修复并另存 |
| 只剩 disabled 副本 | 警告 | 文件被移到了 `disabled` 目录，但开关记录仍是开启 | 从 `disabled` 移回，或关闭该条目 |
| 同名路径是文件夹 | 警告 | `addonlist.txt` 记录了某个 Mod，但磁盘上的**同名路径是一个文件夹**：游戏只加载 `*.vpk` 文件，同样不会生效（若 `disabled` 里还有一份可用文件，提示会写出来） | 把那个文件夹改名，或把真正的 `.vpk` 放回原位 |
| 条目指向受管目录之外 | 警告 | 条目用 `..\` 之类写法解析到了 `addons` / `workshop` / `disabled` 之外（手改过文件、别的工具写过、或旧版本残留）。游戏不会按预期加载它，而只看"文件是否存在"是发现不了的 | 把条目改回受管目录里的相对路径（在「Mod 管理」里重新开关一次即可写回正确键） |
| 工坊作品有多份副本 | 警告 | 同一件工坊作品在根目录与 `workshop` 目录各有一份（`123.vpk` 与 `workshop\123.vpk`）。只会白占空间，而且两处都能被开关（addonlist 键不同），很容易开错那份 | 只保留一份：留工坊原件、把根目录那份移走（可用「移动到…」放到别处）或删除（进回收站）。体检**只提示，不自动删** |
| 重复条目 | 警告 | 同一个 Mod 在 `addonlist.txt` 中出现多次 | 点击“清理重复条目” |
| 孤立的工坊信息 | 提示 | 存在 `xxx.meta` 但没有对应的 `xxx.vpk` | 可以安全删除该 `.meta` |
| 缺少工坊信息 | 提示 | `workshop` 目录里的 VPK 缺少同名 `.meta`（仅在开启“工坊信息存储”时提示） | 重新下载或更新一次该 Mod |
| 工坊信息对不上作品 | 警告 | `workshop\<ID>.meta` 里记录的工坊作品 ID 与文件名不是同一个作品：更新检测会拿**另一个作品的时间戳**做比较，可能漏报或误报更新 | 在「设置 → 工坊设置」点“抓取官方标签与统计”重新抓取该 ID，或删掉这个 `.meta` 让它重建 |
| 依赖未开启 | 警告 | 主 Mod 已开启，但它声明的依赖处于关闭状态 | 点击“启用缺失依赖”，或在“Mod 依赖”里单独启用 |
| 依赖缺失 | 警告 | 依赖声明指向的文件在磁盘上找不到 | 重新下载该依赖，或删除这条依赖声明 |
| 依赖成环 | 警告 | A 依赖 B、B 又依赖 A（或更长的环），两边互相等待 | 删掉其中一条依赖声明（报告里会写出完整链路） |
| 未写入开关记录 | 提示 | 磁盘上有 Mod，但没有写进 `addonlist.txt` | 用游戏内开关或管理器启用一次即可记录 |
| 缺少 addonlist.txt | 警告 | 游戏还没写过开关状态文件 | 先进一次游戏或手动创建 |

## 在结果里搜索（问题多的时候特别有用）

体检结果上方的搜索框和 Mod 列表、压缩包管理、模型统计、策略组管理、冲突检测用的是**同一套语法**：

| 写法 | 含义 |
| --- | --- |
| `ak47` | 普通词（可多个）：问题对象名、文件路径、可操作目标、提示文案都算 |
| `addonlist 依赖` | 两个词要同时命中同一条问题 |
| `-tag:缺少工坊信息` | 排除「包含」这个类型的问题（子串匹配，长路径不会误伤） |
| `tag:严重` | 按严重度筛：严重 / 警告 / 提示 |
| `tag:条目缺少文件` | 按问题类型筛（类型名与列表里显示的一致，例如「同名路径是文件夹」） |
| `re:\.vpk$` | 正则匹配；写错了会直接提示「正则表达式无效」 |

**为什么值得用**：体检查出的问题可能成百上千（例如工坊 Mod 没抓过官方信息时，
每个 VPK 都会产生一条「缺少工坊信息」）。列表一次只显示前 100 条，
以前剩下的只能靠翻；现在可以直接 `-tag:缺少工坊信息` 把噪音排掉，
计数栏会写清「匹配 3 / 943 个问题」，并提示还有多少条未显示。

搜索只影响**显示**：体检结果本身、一键修复、报告导出都不受影响
（导出的报告仍然是完整结果）。搜索框旁的 **`?`** 是这份语法的说明书，按 `Esc` 清空。

体检发现“重复条目”后，“清理重复条目”按钮会变为可用。它会保留每条的第一个记录、删除后续重复项。

## 清理失效条目

体检发现“条目缺少文件”后，“清理失效条目”按钮会变为可用。它会删除那些在 `addons`、`workshop`、`disabled` 三处都找不到文件的条目。

注意：工坊 Mod 的文件被删除（例如暂时退订）时，条目也会被判为失效。清理后如果文件重新下载，游戏会按默认状态加载它，而不是沿用原来的开关。

两种清理都会在写盘前建立一份“体检修复前”备份，可在同页的“历史备份”里恢复。

## 哪些问题能一键修复（自动修复分级）

体检结果里的每一条都带一个类型，只有**确实不需要你判断、且能安全回退**的类型才会给出「修复」按钮：

| 类型 | 能否一键修复 | 修复动作 |
| --- | --- | --- |
| 重复条目 | 可以 | 保留第一条，删除后续重复项（写前先建 `before-health-fix` 备份） |
| 条目缺少文件 | 可以 | 删除在 `addons` / `workshop` / `disabled` 三处都找不到文件的条目 |
| 依赖未开启 | 可以 | 给**这一条问题的主 Mod** 启用它声明的全部依赖（文件缺失的依赖会跳过并在提示里报告）；不动别的 Mod。写前先建 `before-dependency-fix` 备份 |
| 其它所有类型 | 不可以 | 保持"只给建议"，由你自己处理 |

报告顶部会先给一句汇总，例如「其中 3 项可以自动修复，点右边的“修复”按钮即可」，
每个可修复的行右侧会出现 **「修复」** 按钮。点它之后：

1. 弹出应用内的确认框（不是浏览器原生对话框），说明这次会改动什么；
2. 确认后先建立备份，再改写 `addonlist.txt`；
3. 写盘、内存状态刷新、受保护快照同步是一个整体，任何一步失败都会回滚到改动前的状态；
4. 完成后重新跑一次体检刷新结果。

**为什么不全自动修**：能自动修的只有"删掉一条已经不可能生效的记录"或"把声明过的依赖打开"这类
单向、可回退、意图明确（依赖是你自己声明过的）的动作。像"只剩 disabled 副本""同名路径是文件夹"
这类需要你判断意图的问题，自动改反而是替你做了决定，所以它们永远只出现在建议里。

## 导出体检报告

体检完成后可以：

- **复制报告**：把结果转成 Markdown 复制到剪贴板，适合直接贴到社区、群聊或 Issue 里求助。
- **保存报告**：写入配置目录的 `reports/` 文件夹（文件名形如 `mod-health-20260922-103000.md`），
  并自动打开文件所在位置。重复保存会自动加序号，不会覆盖旧报告。

报告按严重程度分节（严重 / 警告 / 提示），每条包含类型、对象和说明；
名称与说明里的竖线会被转义，保证表格在 Markdown 里正常显示。

## 注意事项

- 体检本身**只读**：不会修改 `addonlist.txt` 或任何 VPK 文件。
- 只有“清理重复条目”和“清理失效条目”会写文件；两者都只删除条目，不改变保留条目的开关与顺序。
- “未写入开关记录”只代表管理器无法判断状态，并不等于该 Mod 没有生效；
  Steam 订阅的工坊 Mod 在未记录时通常仍会被游戏加载。
