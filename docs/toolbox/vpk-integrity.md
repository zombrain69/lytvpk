# VPK 完整性检测

“VPK 完整性检测”用来判断一个 VPK **能不能被游戏正常读取**：检查归档目录树、每个条目的校验和，
以及根目录 `addoninfo.txt` 的语法。发现问题时可以**安全修复**——修复产物是**另存的新文件**，原文件永远不动。

入口：**工具箱 → 通用工具 → VPK 完整性检测**；在「MOD 管理」列表里**右键多选**也能批量检测与修复。

## 它检查什么

| 检查项 | 说明 |
| --- | --- |
| 归档目录树 | `vpk` 的目录段 / 文件名 / 扩展名结构是否合法、路径是否安全 |
| 条目校验和 | 每个文件条目的 CRC 与数据是否对得上（下载不完整、被截断、被错误重打包都会在这里暴露） |
| `addoninfo.txt` | 游戏认插件用的根目录元数据：语法是否合法、`addonTitle` 等字段是否存在 |

报告会给出 `valid` / 问题列表。**不可读的文件（例如把 ZIP 改名成 `.vpk`）会直接报错**，
并提示"文件头不是 VPK，请确认没有错误重命名或下载不完整"。

## 怎么用

### 单个文件

1. 工具箱 → 通用工具 → **VPK 完整性检测** → 选择 `.vpk`。
2. 看报告：合法就结束了；有问题会列出具体条目与原因。
3. 点修复：生成一份修复后的副本，**原文件不动**。

### 批量（推荐）

1. 在「MOD 管理」里勾选多个 Mod（支持框选 / `Ctrl` 多选）。
2. 右键 → **VPK 完整性检测**：每个文件单独出结果，先给一份汇总，再**一次确认**批量修复。

## 修复会做什么（以及不会做什么）

- **不覆盖原文件**：产物命名为 `原名.repaired.vpk`，重名时自动加序号（`(1)`、`(2)`…）。
- **尽量保真的重建 `addoninfo.txt`**：格式良好的 KeyValues 原样保留（包含你不认识的字段与嵌套结构）；
  内容被截断时用容错解析尽量抢救，**已有非空字段优先**；缺 `title` / `description` 时才用同名 `.meta` /
  工坊元数据兜底，并把"哪些字段是推导出来的"写进修复摘要。
- **顺带带上 sidecar**：同名图片、`.meta` 等伴随文件会跟着新文件名一起复制过去。
- **不会自动替换游戏里的 Mod**：修好后确认没问题，再自己把 `.repaired.vpk` 改名/移动回 `addons`。

## 什么时候该用

- 游戏里"这个 Mod 装了但加载不出来/报错"，其它工具又看不出问题。
- 从网盘、压缩包里拿到的 VPK 不确定是否完整（截断文件在这里一定会暴露）。
- 改过文件名、重新打包过之后想确认归档结构仍然合法。
- 上传服务器面板被拒（部分服务端会校验归档），先用它过一遍。

> 体检（设置 → 游戏配置 → Mod 体检）里的 `invalid_vpk` 是"扫一遍全库，找出读不出来的那些"；
> 这里是对**指定的一个或一批文件**做详细检查与修复。两者配合用：体检找目标，完整性检测修文件。
