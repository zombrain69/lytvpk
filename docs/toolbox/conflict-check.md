# Mod 冲突检测

“Mod 冲突检测”用于检查多个 VPK 是否包含相同路径的资源文件。

## 作用

当两个 Mod 修改同一个模型、材质、脚本或音频时，后加载的文件可能覆盖前面的文件。冲突检测可以列出这些覆盖关系。

## 使用步骤

1. 打开“工具箱”。
2. 点击“Mod 冲突检测”。
3. 等待扫描完成。
4. 查看冲突文件组和涉及的 Mod。

## 在结果里搜索

结果上方的搜索框和 Mod 列表、压缩包管理、模型统计、策略组管理用的是**同一套语法**：

| 写法 | 含义 |
| --- | --- |
| `ak47` | 普通词（可多个）：资源路径与参与 Mod 名都算，字符按顺序出现即命中 |
| `materials ak47-cn` | 两个词可以分别命中路径与 Mod 名 |
| `-katana` | 排除**包含** katana 的冲突组（子串匹配，长路径不会误伤） |
| `tag:严重` | 按严重度筛：严重 / 警告 / 提示 |
| `tag:同层` | 只看"参与者共用同一个有效分层"的真冲突；另有 `未记录`（有 Mod 没写进 addonlist） |
| `tag:同层 -tag:严重` | 条件可以组合（且 / 排除） |
| `re:\.nut$` | 正则匹配；写错了会直接提示「正则表达式无效」 |

搜索与上方的严重度筛选是**「与」**的关系；命中片段会在 Mod 名里高亮，
右侧显示 `匹配 2 / 5 个组冲突`。搜索框旁的 **`?`** 是这份语法的说明书。按 `Esc` 清空检索。

## 结果怎么看

结果通常会按严重程度显示：

- 严重：可能直接影响游戏内容或导致明显覆盖。
- 警告：可能有影响，需要结合实际 Mod 判断。
- 信息：存在重复文件，但不一定有问题。

如果开启了“按加载顺序判定胜负”，结果会分成两类：

- **冲突**：至少有一个 Mod 没有写入 `addonlist.txt`，先后顺序无法确定，胜负未知。
- **覆盖关系**：所有涉及的 Mod 都能在 `addonlist.txt` 中查到顺序，会直接给出谁生效、
  谁被覆盖。这类重叠不再计入冲突数量，但仍在结果下方单独列出，方便你调整顺序。

## 按加载顺序判定胜负

开启方式有两种，改的是同一份配置：

1. 在“Mod 管理”页打开“冲突分析范围”弹窗，勾选“按加载顺序判定胜负”。
2. 在“设置 → 游戏配置 → Mod 冲突分析”里打开同名开关，作为默认行为长期生效。

开启后需要读取 `addonlist.txt`：其中被标记为关闭的 Mod 不参与判定；
没有写入 `addonlist.txt` 的 Mod 会让相关重叠继续显示为冲突。

## 如何处理

常见处理方式：

- 禁用其中一个 Mod。
- 调整加载顺序：覆盖关系卡片里的“提前 / 延后”可以直接改变生效方。
- 给 Mod 添加标签，避免以后同时启用。
- 如果只是相同的说明文件或预览资源，可以加入忽略清单。

## 冲突忽略清单

“设置 → 游戏配置 → Mod 冲突分析”里可以维护忽略清单，每行一个 VPK 内部路径：

- `materials/shared.vtf`：忽略这个具体文件。
- `scripts/vscripts/`：忽略这个目录下的所有文件（以 `/` 结尾表示目录）。
- 以 `#` 或 `//` 开头的行是注释，不会生效。

清单对所有冲突检测入口生效，用于屏蔽预览图、脚本公共文件等“注定重复”的路径。

## 单个 Mod 的忽略清单

有些重复只对**某一个 Mod** 才是噪音：例如某个整合包自带一份 `materials/shared.vtf`，
而你并不想让它参与这条路径的冲突判定。这时用“该 Mod 自己的忽略清单”更精确：

1. 在 Mod 管理页打开该 Mod 的**详情**。
2. 找到“该 Mod 的冲突忽略文件”，按每行一个路径填写（规则与全局清单相同，
   以 `/` 结尾表示目录）。
3. 点“保存忽略清单”。清空内容后保存，或点“清空”，表示删除这份清单。

规则语义：

- 命中这些路径时，**只有这个 Mod** 退出对应资源的重叠判定；
  它不会影响其它 Mod 之间的冲突，也不会修改任何文件。
- 内置忽略规则和设置页的**全局清单**始终生效，三者的关系是并集。
- 被自身规则跳过的重叠会在冲突检测结果里以“因 Mod 自身的忽略规则跳过”单独列出，
  这样你能解释“为什么刚才还报冲突，现在不报了”。

对应说明：该 Mod 自己的清单保存在配置目录的 `ignore.json`，与 `dependencies.json` 同级。

## 注意事项

## 自动复检与修复建议

只要游戏侧状态发生变化（开关写入 `addonlist.txt`、应用方案 / 策略组、启用依赖、
移动 / 重命名 / 删除 Mod），应用会把冲突分析结果标记为"待复检"：

- Mod 列表上的角标会显示该 Mod 当前的 `N 处冲突 / N 处覆盖`，不用手动打开工具重新扫描。
- 打开冲突检测时，结果下方会给出"修复建议（需要你确认）"，例如
  "这两个 Mod 的有效分层相同，建议把其中一个抬高一层"。
- 点建议里的按钮只会写入 `priority.json`（分层），**不会自动重排 `addonlist.txt`**；
  要真正改变游戏侧顺序，仍需到“编辑加载顺序”里点“按分层应用”。

自动复检复用已有的 VPK 索引缓存，未修改的 VPK 不会重复解析。

## 游戏原版文件白名单

很多 Mod 会附带一份**原版文件的完整副本**（引擎胶水文件、原版脚本等）。
两个这样的 Mod 在同一条原版路径上"重叠"并不代表它们真的冲突，属于典型误报。
原版文件白名单用于把这类路径排除在冲突判定之外。

规则：

- 白名单**只用于忽略**，不会改写任何 Mod 文件，也不会改写游戏文件。
- 默认启用内置批次（`addoninfo.*`、`sound/sound.cache`、几个原版 `*_addon.nut`）；
  这些路径同样是上游 FireAxe 的内置忽略集合，并且已用本机 `pak01_dir.vpk` 核对存在性。
- 可按类别从本机原版资源包生成增量批次：
  “设置 → 游戏配置 → Mod 冲突分析 → 游戏原版文件白名单 → 从原版 pak01 生成批次”。
  生成结果是配置目录 `stock-files/` 下的 `<类别>.txt`（例如 `models.txt`、`materials.txt`），
  每个文件一个类别，**删除文件即可停用该类别**。
- 批次缺失或解析失败时只跳过该批次，冲突检测照常工作（降级为内置规则）。

注意：生成整类白名单（例如 `models.txt`）会屏蔽该类别下所有原版路径的冲突提示。
如果你更在意原版模型 / 材质的替换冲突，请不要生成对应类别，或生成后删除该文件。

冲突检测只能发现“文件路径相同”的覆盖关系，不能保证判断所有脚本逻辑冲突或运行时问题。
另外，加载顺序的方向（靠后生效还是靠前生效）以游戏实际行为为准，
本项目会持续按实测结论校准。
