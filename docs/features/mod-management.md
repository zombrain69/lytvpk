# MOD 管理

“MOD 管理”是主页面，用来查看、筛选和操作当前 `addons` 目录中的 VPK 文件。

![MOD 管理卡片视图预览](/mod-management-preview.png)

## 文件列表和卡片

应用支持列表和卡片两种显示方式：

- 列表适合快速比较文件名、大小、位置和标签。
- 卡片适合查看预览图和更直观地浏览 Mod。

显示方式可以在“设置”里的“界面设置”切换。

## 搜索、筛选和排序

页面顶部提供搜索框、位置筛选、标签筛选和排序。

- 搜索：按文件名、标题等信息查找。
- 位置筛选：查看 addons、workshop、disabled 等位置的文件。
- 标签筛选：按地图、人物、武器、音频等类型筛选。
- 排序：按**优先级**、文件名、日期、大小或模型复杂度排序。

### 默认排序：优先级

列表默认按**优先级**排序（排序按钮显示“优先级排序 (顺序)”），规则是：

1. 先比较**有效分层**（在“编辑加载顺序”里设置的优先级分层，或策略组权重算出来的值），
   数值越小越靠前，也就是越先加载；
2. 同一层内按 `addonlist.txt` 的**真实顺序号**排列，保证与游戏实际加载顺序一致；
3. 没有写入 `addonlist.txt` 的 Mod 排在最后，并按文件名排列。

没有设置任何分层时，第 1 条退化为第 2 条，排序结果与以前的“按加载顺序排序”完全相同。
在排序菜单里可以随时切换成文件名、日期、大小或模型复杂度排序。

点“重置筛选”可以回到默认列表。

## 标签管理

每个 Mod 都可以设置一级标签和多个二级标签。

- 一级标签用于大分类，例如地图、人物、武器。
- 二级标签用于细分，例如角色名、武器类型或自定义备注。
- 批量设置标签可以同时整理多个文件。

标签适合给难以识别或自己重命名过的 Mod 做补充说明。

## 启用和禁用

启用表示 Mod 会被游戏加载，禁用表示暂时不让游戏加载。

常用操作：

- 单个启用或禁用。
- 批量启用或禁用选中文件。
- 一键禁用全部 Mod。
- 只禁用人物类或武器类 Mod。

批量操作前请检查选中数量，避免误改不相关文件。

如果 VPK 缺少或损坏 `addoninfo.txt`，管理器不会再强制拒绝启用或其他文件操作。执行相关操作前会显示显眼的完整性风险提示：你可以取消、直接继续，或打开“VPK 完整性检测”进行修复并另存为。游戏仍可能忽略、移除或无法加载这类 Mod。

## 隐藏文件

隐藏适合处理你暂时不想在列表里看到，但又不想删除的 Mod。常见用法是把长期固定使用的日常 Mod 隐藏起来，只在列表里维护每天要玩的地图文件。

- 选中文件后可以批量隐藏。
- 开启“显示隐藏”后可以查看和取消隐藏。

隐藏不会等同于删除，也不一定表示禁用。

## 加载顺序

部分 Mod 会因为覆盖同一资源而受到加载顺序影响。加载顺序越靠后，通常越容易覆盖前面的资源。

你可以在文件操作菜单中打开“编辑加载顺序”，调整单个 VPK 的顺序。

### 优先级分层（可选）

加载顺序是"文件里的第几行"，分层是"你希望谁覆盖谁"的可编辑意图。两者分工明确：

- **真实加载顺序始终以 `addonlist.txt` 为准**，分层不会变成第二份真相。
- 分层是整数，**数值越小越先加载**，可以是负数。
- 不设置分层时，该 Mod 的优先级完全等于它在 `addonlist.txt` 里的顺序号，行为与以前一模一样。

设置方法：打开“编辑加载顺序”，在“优先级分层”里填写数值（或用 −1 / +1 微调）后点“保存分层”。
**保存分层本身不会改动 `addonlist.txt`**；只有点击“按分层应用（重排 addonlist.txt）”才会按分层重排文件，
重排前后的开关状态、编码与 BOM 都保持不变，并且同层内维持原有相对顺序。

策略组可以设置"组权重"，组权重会叠加到组内成员：最终生效的分层取
`min(Mod 自己的分层或顺序号, 所属策略组的权重)`。同一 Mod 属于多个带权重的策略组时取最小值，
因此**组权重只会让 Mod 更靠前，不会因为分组变化来回漂移**。

冲突检测会使用同一套分层：分层相同的重叠属于真冲突（先后顺序未定义），
分层不同的重叠属于覆盖关系，显示“生效 / 被覆盖”。列表与冲突卡片上的
`优先级 #顺序（分层 T）` 标签就是这套规则的可视化。

## 启用方案

“启用方案”把当前 `addonlist.txt` 的**开关状态与加载顺序**整体保存下来，方便在不同玩法之间切换。

在“设置 → 游戏配置 → 启用方案”里可以：

- 输入方案名称后点击“保存当前为方案”，记录当前的启用组合与顺序。
- 勾选“同时保存策略组与依赖”后再保存：方案会一并快照当前的**策略组**、**依赖声明**与
  **优先级分层**，应用时整体恢复（会覆盖本地现有的策略组、依赖与分层记录，
  恢复的组会重新分配内部 ID）。
- 点击某个方案的“应用”，一键切回这套组合；应用前会自动备份当前 `addonlist.txt`，
  备份会出现在同页的“历史备份”里，类型为“应用启用方案前”。
- “导出”把方案保存成文件分享给别人，“导入方案”可以读取别人分享的文件。

应用规则：

- 方案里记录的 Mod 会恢复成保存时的开关，并按保存时的顺序排列。
- 方案里记录、但当前 `addonlist.txt` 中已缺失的 Mod：会按方案补回（不会动磁盘上的 VPK 文件）。
- 方案保存之后才新增的 Mod：**保留原开关**，统一排在方案条目之后，不会被静默禁用。
- 未勾选“同时保存策略组与依赖”的方案只恢复开关与顺序，不会改动本地的策略组与依赖。

## 随机轮换

“Mod 随机轮换”用于按配置随机启用一部分 Mod，适合人物、武器等想轮流体验的内容。

推荐流程：

1. 下载一批你喜欢的 Mod。
2. 确保每个 `.vpk` 文件对应一个 Mod。如果某个 Mod 有多个文件，需要先自行合并。
3. 查看每个 Mod 的标签是否正常。如果自动识别不准确，可以手动修改标签，尤其是作者命名比较混乱的 Mod。
4. 打开管理器里的轮换功能开关。
5. 点击管理器内的“启动 L4D2”按钮，或通过收藏服务器连接进游戏。
6. 开玩。

使用前建议先整理好标签，这样轮换范围更可控，也能减少随机到错误类型 Mod 的情况。

## 策略组

策略组是“一组 Mod + 一个应用策略”，适合角色替换包、武器替换包这类互相冲突的套装。

### 建组与整组管理（MOD 管理页）

日常操作全部集中在 MOD 管理页工具栏的**「分组」**菜单里，不需要先去设置页：

| 想做什么 | 在哪里 | 行为 |
| --- | --- | --- |
| 只看某一组 | 工具栏「分组」→ 勾选组名 | 列表立即只显示该组成员（可多选、可「清空」） |
| 整组开关 | 菜单里的「整组开关」，或直接单击卡片上的组徽标 | 按组内当前多数状态取反，**只改 `addonlist.txt` 的 0/1**，不重排、不动 Mod 文件 |
| 整组移动优先级 | 菜单里的「↑ 前移 / ↓ 后移」 | **只写 `priority.json` 的分层**（每次 5 层）；要真正重排 `addonlist.txt`，仍需到「编辑加载顺序」点「按分层应用」 |
| 把勾选的 Mod 存成一组 | 菜单里的「用选中的 Mod 建组」 | 弹出应用内输入框填写组名，只写 `groups.json` |
| 把勾选的 Mod 加进已有的组 | 菜单里的「＋ 选中的 N 个」 | 只往 `groups.json` 追加成员；重复加入是幂等的，已经在组里的会跳过 |
| 把勾选的 Mod 移出一个组 | 菜单里的「－ 选中的 N 个」 | 只从 `groups.json` 移除成员；不允许把成员全部移出（要清空请直接删除组） |
| 改组名 / 改描述 | 菜单里的「重命名」 | 应用内输入弹窗；成员、权重、层级、策略都不受影响 |
| 删除组 | 菜单里的「删除」 | 应用内确认弹窗会先说明影响范围；只删 `groups.json` 的这一条，不动 `addonlist.txt` 与 Mod 文件 |
| 让工具猜哪些 Mod 像同一组 | 菜单里的「分组建议」 | 打开推导弹窗，勾选/改名后「创建为组」 |

组徽标显示为 `组：<组名>`，鼠标悬停会说明「单击整组开关；整组优先级前移/后移在工具栏「分组」菜单里」。
建组、删除、整组开关之后，徽标与分组筛选菜单都会立即刷新。

### 对单个 / 选中的 Mod 直接改分组（单文件菜单与多选菜单）

除了按组操作的「分组」菜单，**任意一个 Mod（右键卡片）或任意一批选中的 Mod（多选后右键）**
都能直接改分组，不需要先打开分组菜单：

| 菜单项 | 出现条件 | 作用 |
| --- | --- | --- |
| **加入策略组…** | 只要选中项有可用的 addonlist 键 | 弹出选择器列出全部策略组（带成员数），选一个就加入；也可以在同一个弹窗里**新建一个组并直接放进去** |
| **从策略组移出…** | 选中项至少属于一个策略组 | 选择器列出它所属的组，选一个就移出（把整个组移空会被拦下） |
| **移动到其它策略组…** | 选中项至少属于一个策略组 | 选目标组后，**一次写盘**完成"从旧组移出 + 加入新组"；只属于一个组时直接选目标，分散在多个组时先选"从哪个组移动" |

选择器本身按"够便捷"来做：

- **搜索**：顶部搜索框在打开时自动聚焦，按 **组名 / 上级分组名 / 策略名** 实时过滤（支持中文），
  并显示「显示 X / Y 个组 · N 个可操作 · 已按筛选隐藏 M 个」；
- **只看相关**：只列包含选中 Mod 的组；「从策略组移出…」默认开启，加入模式默认关闭；
- **排序**：可点的组优先 → 含选中 Mod 的优先 → 按名称（中文拼音）；
- **键盘**：`↑` / `↓` 在可点行之间移动高亮（自动滚进视野）、`Enter` 确认、`Esc` 关闭；
  「新建并加入」输入框里回车即建组；
- **双击**：在行上双击 = 选中并直接执行，省掉"点单选 + 点确认"两步；
- 每一行显示策略（互斥单选 / 全部开启 / …）、成员数、`权重 N`、`自动联动`、`上级：X` 等标签，
  以及"选中里已有 N 个"；对当前操作没有意义的行（已经全在组里、会把整组移空等）会置灰并说明原因。

这些动作都只写 `groups.json`：不改 `addonlist.txt`、不动 Mod 文件、不改 `priority.json`。

**「策略组管理」独立窗口**（Mod 管理页「分组 → 策略组管理…」，或设置页那张卡片上的
「打开策略组管理窗口…」按钮）提供同一套生命周期动作：**按策略应用 / 随机单选 / 全关 /
重命名 / 删除**，外加**组权重**与**上级分组**。窗口可以拖动边缘自由缩放，组很多时列表在窗口内滚动；
ESC 或点击窗口外的遮罩即可关闭。删除同样使用应用内确认弹窗
（WebView2 的原生 `confirm` 在锁屏或自动化环境下会阻塞页面），并会提示下级分组会被提升到顶层。

每个组行还有 **「展开成员（N）」**：展开后逐行列出该组成员，并带上位置（根目录 / 创意工坊 / 已禁用）、
游戏开关、优先级（或"未写入 addonlist"）徽标，以及 **详情 / 游戏开关 / 启用·禁用 / 复制到 addons /
移出本组** 五个按钮 —— 与「分组建议」卡片里展开成员时看到的是**同一套成员行**
（`frontend/src/js/features/mod-groups/member-row.js`），所以在管理组的时候就能直接把 Mod 选项配好，
不必再回列表里找。展开状态在窗口重画 / 刷新后保持。

### 「上级分组」与「按分组筛选」的关系

这两个是**互相独立**的东西，别把它们当成一层：

- **上级分组（层级）**：只决定"这组挂在哪个组下面"，在管理窗口里表现为缩进与
  `└` 前缀；它**不影响** Mod 的开关、排序与优先级。它跟「按分组筛选」唯一的关系是：
  筛选菜单里的组名也会用 `└` 标出层级，让你知道它属于哪个上级分组。
- **按分组筛选**：是主界面的一个**多选筛选器**（只改变"列表显示哪些 Mod"）。
  它的**顺序 = 组权重升序**（未设置权重的组排最后，同权重按名称），
  也就是"把需要经常编辑的组填个更小的权重，它就会排到最上面"。
  **子组永远紧跟自己的上级分组**（整棵分组树一起移动），子树的位置取"子树里最小的权重"——
  所以给子组设权重，整棵树会一起上浮，而子组仍缩进显示在父组下面；
  这样 `【…】`、`!…` 这类不同前缀也不会把同一棵树拆散。
  菜单顶部有一行 `顺序＝组权重（未设置排最后）· 子组紧跟上级分组` 作为说明。
  在管理窗口里改完权重 / 上级分组 / 组名 / 自动联动后，这份菜单与主列表会**立即**刷新。

**在管理窗口里直接筛选**：组行有 **「筛选这组 / 取消筛选」**，批量工具条有
**「用选中的组筛选」** 与 **「清除筛选」**，窗口里还会显示 `当前筛选：A、B`，
正在筛选的组整行高亮。它改的就是主界面那份筛选状态（不写任何文件），
所以两边永远一致：在窗口里筛完，关掉窗口或直接用主界面看，都是同一批 Mod。

**浮动窗口**：管理窗口默认以浮动方式打开（可关）：窗口**不再有遮罩、也不会把主界面虚化**，
能一边看管理窗口一边点「分组 / 按分组筛选」，标题栏可拖动、边缘可缩放；
关掉「浮动窗口（可直接操作主界面）」就回到原来的模态行为（遮罩 + 背景模糊 + 点窗口外关闭）。

这套「浮动窗口」是通用能力（`frontend/src/js/core/floating-modal.js`），
复杂的管理类窗口都接上了，默认浮动：**分组建议 / 加载顺序优化 / Mod 冲突检测 / 文件冲突 /
问题 Mod 查找（体检）/ Mod 模型面数检测**。没有自带开关的窗口会在标题栏自动多出一个
「浮动窗口 / 停靠窗口」按钮；拖动标题栏即可移动，位置按窗口记住；缩放沿用窗口边缘的把手。

### 分组建议（推导）

「分组建议」是**只读推导**：它只读取当前已经扫描到的 Mod 元数据，不会写任何文件、
不会改动 `addonlist.txt`、也不会移动 Mod 本身。可用的信号：

| 信号 | 含义 | 可信度 |
| --- | --- | --- |
| 工坊合集成员 | 你已经保存过「工坊合集」记录，且这些 Mod 都在同一条合集里 | 高 |
| 同一文件夹 | 已扫描到的 Mod 位于同一层文件夹（`disabled` 下可以再建套件文件夹；各层目录分别成组）；`workshop` / `disabled` 本身属于存放位置，不算套件 | 高 |
| 主体识别 | 扫描出的**替换目标**相同，例如「Francis 语音」「Tank 模型」「M16 武器」「吉他 武器」 | 中（内容证据） |
| 语音角色 | VPK 里替换了同一个角色的语音（来自标准 `sound/player` 目录），例如「Nick 语音」 | 中（内容证据） |
| 共同标签 | **任意两个**二级标签相同（不限前两个标签），例如「AK47、皮肤」 | 中（内容证据） |
| 同名文件（不同目录） | 同一套件内文件名相同但目录不同，例如「角色动画版 / 角色无动画」这类同一 Mod 的不同版本 | 中（内容证据） |
| 文件名前缀 | 文件名首个词（过短时取前两个词）相同，例如同一个系列 | 低 |
| 同一作者 | `addoninfo.txt` 里作者相同，且作者名是单人署名 | 低 |

排序遵循「内容证据优先」：`工坊合集 / 文件夹` → `主体识别 / 共同标签 / 同名变体` →
`文件名前缀 / 同一作者`。也就是说**武器归武器、角色归角色**：
「M16 武器」只会收替换 M16 的 Mod，「Francis 语音」只会收 Francis 的语音包，
不会把武器和 HUD 混进同一组。

### 标签 × 分组：两个方向互补

标签（写在文件名 `[标签]名字.vpk` 里）和策略组本来就是两种"分类"手段，这里让它们互相利用：

**方向一：标签已经能筛出来的，不再重复推荐建组。**

如果某个标签**恰好只能筛出这一批 Mod**（集合内全命中、集合外没有别的 Mod 带它），
那建组就没有增量价值。这类建议会被标注「标签已覆盖：xxx」并**默认隐藏**：

- 筛选栏新增「隐藏标签已覆盖 / 显示全部 / 只看标签已覆盖」；
- 概要行会写明「N 条标签已覆盖（可直接用标签筛选）」；
- 展开这类建议时，卡片上带一个「用标签筛选」按钮：点了会关闭弹窗并直接按那个标签筛选，
  效果与建组一致（例如"全是替换 sg552 的枪"这种）；
- 只覆盖一部分（集合外还有别的 Mod 带同一标签）的建议**不会**被隐藏——
  那种情况下标签筛出来的是更大的集合，建组仍然有意义。

**方向二：用高精度的组（尤其是外部 agent 导入的建议）反过来把标签补准。**

自动标签靠规则命中，未必准；而外部智能体导入的分组建议是"看过内容"的判断。
所以「分组」菜单里每个组都有 **「打标签…」**：

1. 工具先给出**建议标签**，来源有三种（会在对话框里写明）：
   - 该组已有的**共同标签**（用它补齐还没打标签的成员）；
   - **组名**（例如组名 `M16 武器` → 标签 `M16 武器`；组名过长时自动放弃）；
   - 成员共同的**主体识别**结果（例如 `sg552 武器`）。
2. 标签名可以直接改；对话框会列出这一组的成员与"已经有这个标签、会被跳过"的数量。
3. 点「给这组打标签」后，标签写进文件名（工坊 Mod 写进同名 `.meta`）。
   **这一步会改变 addonlist 键**，所以工具会自动把策略组 / 优先级分层 / 依赖 / 冲突忽略清单里的
   旧键改绑到新键（与"重命名 Mod"走同一套逻辑），不会因为打标签而掉组。

这样一条链路就闭合了：外部建议（高精度）→ 建组 / 打标签（沉淀）→ 以后靠标签筛选
（不必再为同类 Mod 重复建组）。

### 建议弹窗：先扫一遍，再决定看哪条

建议可能上百条（实测导入 189 条 + 内置 45 条），所以弹窗默认是**折叠卡片**形态，
用来一次性浏览尽量多条；需要动手时再展开：

- **折叠卡片**：标题 + 置信度徽标 + 来源徽标（导入建议）+ 成员数 + 推导理由 + 信号标签 +
  成员预览（前 3 个，后面显示「…还有 N 个」），右下角一个「展开详情」。
- **展开详情**：标题变成可编辑的组名输入框，成员按行列出，和「Mod 冲突检测」的列表一致：
  标题 + 文件名（同名条目靠文件名区分）+ 位置徽标（根目录 / 创意工坊 / 已禁用）、
  游戏开关徽标（开 / 关 / 未记录）、优先级徽标（`优先级 #N（分层 N）`），
  以及每个成员的 **详情 / 游戏开关 / 启用 · 禁用 · 复制到 addons**（按位置决定）按钮。
  每条建议可以整体「全选 / 全不选」，改完组名再「创建为组」；折叠状态也能直接「创建为组（N）」。
- **筛选与排序**：搜索框按组名 / 成员名 / 信号搜索，另有置信度（高 / 中 / 低）、
  来源（导入建议 / 内置推导）下拉，以及排序方式（推荐顺序 / 置信度优先 / 成员多优先 / 名称顺序）。
  想先看最靠谱的就选「置信度优先」。
- **窗口可以拖动缩放**：拖右下角即可放大或缩小，尺寸记在本地（`localStorage`），下次打开保持；
  「全部展开 / 全部折叠」一键切换当前筛选结果的形态。
- **分页渲染**：每次先渲染 24 条，底部「显示更多建议」逐页加载；筛选栏右侧实时显示
  「显示 X / Y 条建议」。这样 200+ 条建议时弹窗依然流畅。

这些按钮只作用于单个 Mod 或这一条建议：不会自动建组、也不会改动其它 Mod 文件。

### 让大模型 / 人工来推导（导入建议文件）

内置推导只能看元数据；如果你想让"看过 Mod 内容"的推导方（大模型、人工整理、外部脚本）
给出更准确的分组，可以走标准格式的**导入**流程：

1. 「分组建议」→「导出 Mod 清单…」，得到 `grouping_catalog.json`（键、标题、作者、
   标签、主体、语音角色、所在文件夹）。**导出前会自动重新扫描一遍 mod 目录**
   （`addons` 根目录 + `workshop` + `disabled`，增量缓存），所以你往目录里加/删文件后
   即使忘了点刷新，这份清单也是最新状态；导出期间按钮会显示「正在扫描并导出…」。
   同一个道理，「准备给智能体的材料」也是先扫描、再导出清单 + 复制提示词；
2. 推导方按标准格式写出 `group_suggestions.json`；
3. 用「导入建议文件…」选择它，或直接放到 `%AppData%\LytVPK\group_suggestions.json`
   再点「重新推导」；
4. 导入的建议带「导入建议」徽标、排在最前面，逐条核对后点「创建为组」。

完整格式、字段与校验规则见 [分组建议与外部导入](/features/group-suggestion-import)。

### 让智能体只看该看的东西：处理范围 + 可编辑提示词

提示词的第一条就是**处理范围（硬性）**：本次只处理
`addons` **根目录**（不递归）、`addons\workshop\`、`addons\disabled\` 这三处；
`addons` 下其它自建子目录（例如 `addons\某角色八人包\…`）的 VPK 既不在清单里，
也不应该出现在建议文件里 —— 提示词会要求智能体把它们写进 `notes` 说明而不是编造成员
（清单顶层的 `scope` / `unreadableMods` 也会写明这些预期差异）。

「分组建议」工具栏还有一个 **「编辑提示词…」**：

- 打开后是 LytVPK 内置的那一整套提示词（Markdown），可以直接改；
- 顶部会显示当前用的是"内置默认"还是"你自己的"（含保存时间），并有 `未保存的修改` 提示；
- 占位符一键插入：<code v-pre>{{CATALOG_PATH}}</code> / <code v-pre>{{INBOX_PATH}}</code> /
  <code v-pre>{{MOD_COUNT}}</code>，
  复制或导出给智能体时会替换成本机真实路径；
- **保存**后，「准备给智能体的材料」「复制提示词」「保存提示词…」都会用你这一套；
  **恢复默认**会删掉自定义文件、回到内置版本（会先确认）。
导入过程只读取文件；只有点「创建为组」才写 `groups.json`，不会改动 Mod 或 `addonlist.txt`。

推导还有几条"降噪"规则，都是按真实 Mod 数据校准的：

- 成员超过 8 个后每多一个成员降权 4 分（最多 60 分），所以"3 个成员、证据明确"的小组排在
  "几十个成员、只共享两个通用标签"的粗糙聚类之前；`工坊合集` 与 `文件夹` 是你显式维护的结构，
  不因成员多而降权（上限放宽到 300）。
- 同一批 Mod 命中多个信号（例如主体 + 共同标签）会获得额外加权，排在只命中单一信号的组合之前。
- 「主体：混合包（…）」这类本身表示"内容混杂"的主体不会作为分组依据输出——它们说明这些 Mod
  都同时覆盖多类内容，凑成一组既不能整体开关，也没有共同的优先级含义。
- `addonauthor` 里的占位符（`AUTHOR_NAME`）、多人联名（`A  +  B`、`甲，乙，丙`）与高产作者
  （同一作者超过 12 个成员）都不作为「同一作者」证据。
- 「同一作者 / 同一前缀」的候选如果横跨不同主分类（武器 + HUD），整桶丢弃，不会混合成组。
- 已经整组建过的建议会带「已建组」标记并沉到列表末尾，避免占满 40 条上限后看不到新建议。

### 组与 addonlist.txt 的关系（重要）

**策略组和 addonlist 是两套独立状态**：`addonlist.txt` 决定"游戏内开关 + 加载顺序"，
`groups.json` 决定"哪些 Mod 属于一组 + 策略 / 权重 / 自动联动"。

| 你做的事 | 对 addonlist | 对策略组成员 |
| --- | --- | --- |
| 整组关闭 / 关闭某个成员 | 把对应条目的值改成 `0`（或补写 `0`） | **不变**，成员仍在组里 |
| 手动从 addonlist 删掉某行（外部工具） | 条目消失 | **不变**，成员仍在组里 |
| 把文件移动到 `disabled\` / 从 `disabled\` 移回 | 键不变（`disabled\` 前缀会被忽略），只改值 | **不变**，仍在组里 |
| 删除 Mod 文件（回收站） | 自动清理该条目 | 成员保留为"悬空成员"（文件不在列表里） |
| 重命名 Mod 文件 | 旧条目按新名字更新 | **自动把旧键迁移成新键**（策略组 / 分层 / 依赖 / 忽略清单一起改绑） |
| 把文件重新放回来（同名 / 同工坊 ID） | 重新记录 | **自动重新命中**，不需要重建组 |

界面上的提示：

- 分组菜单里的组名会显示 `组名（N） · 含 M 个缺失`，鼠标悬停说明"放回同名文件会自动回到组里"；
- 「策略组管理」窗口的组列表在缺失的组下方显示黄字 `⚠️ 文件缺失 M 个：…`；
- 删除属于策略组的 Mod 时，会先弹出「该 Mod 还在 N 个策略组里」的提示，确认后才删除。
两条安全细节：

- **应用组时会跳过"文件已不在列表里"的成员**：不会往 addonlist 写幽灵条目，
  操作提示会说明"× 个成员的文件已不在列表里，已跳过"；
- 组操作只改 `addonlist.txt` 的 `0/1`（整组开关）或 `priority.json` 的分层（整组前移/后移），
  **不会删除、移动或重命名任何 Mod 文件**；真正重排顺序仍需到「编辑加载顺序」点「按分层应用」。
### 建组步骤（策略组管理窗口）

1. 在 MOD 管理页勾选要归入同一组的 Mod。
2. 打开 Mod 管理页「分组 → 策略组管理…」（窗口里的按钮会显示「用选中的 N 个 Mod 建组」），填写名称并选择策略。
3. 点击“用选中的 N 个 Mod 建组”。

> 与 MOD 管理页「分组」菜单里的「用选中的 Mod 建组」相比，窗口里可以同时指定策略
> （互斥单选 / 随机单选 / 全部开启 / 全部关闭）与组权重；快捷入口默认建为「互斥单选」，
> 之后可以在窗口里改成其它策略。

每个策略组可以随时执行：

> **批量管理**：策略组管理窗口的组列表每个组前都有勾选框。勾选若干组后，用列表上方的工具条
> 「全选 / 已选 N 个组（M 个成员…）」一次完成 **批量删除**、**开启/关闭自动联动**、
> **设置权重 / 清除权重**。批量删除会先弹应用内确认框并列出组名与影响范围
> （只删 `groups.json` 记录、不动 `addonlist.txt`、不删 Mod 文件、下级分组回到顶层）；
> 批量设置权重只写 `groups.json`，仍需到「编辑加载顺序」点「按分层应用」才会重排。
> 勾选状态在窗口重画后仍保留（不存在的组会自动取消勾选）。

- **按策略应用**：按建组时选的策略执行一次。
- **随机单选**：在组内随机保留一个启用，其余关闭。
- **全关**：把组内成员全部关闭。
- **删除**：移除策略组（不会改动当前 `addonlist.txt`）。
- **自动联动**：开关默认关闭。开启后，手动在列表里开关组内某个成员时，会按策略自动调整同组其它成员。
- **组权重**：填写整数后点“保存权重”。权重会叠加到组内成员的有效分层上（数值越小越先加载，
  多个组取最小值）；留空并保存表示清除权重。保存权重只写 `groups.json`，
  **必须到“编辑加载顺序”里点“按分层应用”才会真正重排 `addonlist.txt`**。

自动联动的行为：

- 互斥单选 / 随机单选：开启某个成员时，自动关闭同组其它成员；关闭成员时不影响其它成员。
- 全部开启：开启或关闭任意成员时，同组其它成员跟随。
- 全部关闭：不触发联动，仅作为一次性动作使用。
- 只联动一层：被联动改动的成员不会再去触发它所在的其他策略组，避免重叠分组互相打架或循环。
- 同一个成员出现在多个“自动联动”组里时，只应用最早保存的那个组。
- 位于 `disabled` 目录的成员不参与联动（游戏本来也不会加载它）。

应用规则：

- 只改动组内成员的开关；其它 Mod 与加载顺序不受影响。
- 组内成员按 `addonlist.txt` 条目匹配，因此 root、`workshop`、`disabled` 目录都能记录；
  已经记录的条目原位改值，没有记录的成员在被开启时按“未记录 Mod 的插入位置”设置补写。
- 默认不做隐式强制：只有该策略组打开了“自动联动”后，单独开关成员才会改动同组其它 Mod。

### 上级分组（树形层级）

每个策略组可以指定一个**上级分组**，用来把相关分组归到一起：

- **默认没有任何上级分组**，此时策略组列表就是原来的扁平列表，行为和以前完全一致。
- 设置上级后，列表里会把下级分组缩进显示在上级下面（最多 4 层）。
- 层级**只影响展示与组织**，不会改变优先级：优先级仍然只由"组权重 + Mod 自身分层"决定，
  避免出现两套互相打架的优先级来源。
- 后端会拒绝"把自己设为上级"、"把上级移到自己的下级里"（成环）以及超过 4 层的设置；
  如果数据里已经存在坏关系（例如上级被删除），读取时会自动把这些组降级为顶层。

### 策略组生命周期一览

| 阶段 | 入口 | 落点 | 备注 |
| --- | --- | --- | --- |
| 创建 | MOD 管理页「分组 → 用选中的 Mod 建组 / 创建为组」、设置页「用选中的 N 个 Mod 建组」 | `groups.json` | 只记录成员键与显示名 |
| 追加成员 | 单文件 / 多选右键菜单「加入策略组…」、「分组 → ＋ 选中的 N 个」 | `groups.json` | 幂等；已经在组里的会跳过 |
| 移出成员 | 单文件 / 多选右键菜单「从策略组移出…」、「分组 → － 选中的 N 个」 | `groups.json` | 不允许移空；要清空请删除组 |
| 换组 | 单文件 / 多选右键菜单「移动到其它策略组…」 | `groups.json` | 一次写盘完成"移出 + 加入"；跨组选择器会先问"从哪个组移动" |
| 重命名 / 描述 | 「分组 → 重命名」、设置页「重命名」 | `groups.json` | 成员与优先级不受影响 |
| 策略 | 设置页策略下拉 + 「按策略应用 / 随机单选 / 全关」 | `addonlist.txt`（只改 0/1） | 默认不隐式强制，除非打开「自动联动」 |
| 组权重 | 设置页「保存权重」 | `priority.json` 的组权重叠加 | 需「按分层应用」才重排 `addonlist.txt` |
| 层级 | 设置页「上级分组」下拉 | `groups.json` 的 `parentId` | 只影响展示，不影响优先级 |
| 删除 | 「分组 → 删除」、设置页「删除」 | `groups.json` | 应用内确认；下级分组提升为顶层；不动 `addonlist.txt` 与 Mod 文件 |
| 文件改名 / 隐藏 | 列表里重命名 Mod | `groups.json` 等四类本地记录 | 自动把旧键改绑到新键，不会掉组 |
| 文件缺失 | 删除 / 移走 Mod 文件 | 组记录保留 | 界面标记「含 M 个缺失」；同名文件放回来会自动回到组里 |

**有意不做**：组内的"成员顺序"（组是集合，加载顺序仍由 `addonlist.txt` 唯一决定）、
把组定义导出成独立文件（当前用 `groups.json` 单文件保存，随备份一起轮转）。

## Mod 依赖

依赖由你自己声明，管理器不会自动推断（工坊数据里没有可靠的依赖关系）。

声明方式：

1. 在 MOD 管理页勾选**主 Mod**和它需要的依赖项（至少两个）。
2. 打开“设置 → 游戏配置 → Mod 依赖”，在下拉框里选择哪个是主 Mod。
3. 点击“把其它 N 个设为依赖”保存。

依赖列表里可以为每条记录执行：

- **启用依赖**：把该主 Mod 的依赖项写入 `addonlist.txt` 并设为开启（文件缺失的依赖会跳过并提示）。
- **删除**：移除依赖声明，不会改动 `addonlist.txt`。

体检（见“Mod 体检”）会提示两类依赖问题：

- **依赖未开启**：主 Mod 已开启，但某个依赖处于关闭状态——可用体检里的“启用缺失依赖”一键补齐。
- **依赖缺失**：依赖声明指向的文件在磁盘上已找不到。

注意：主 Mod 自身处于关闭状态时不会提示依赖问题；依赖只影响提示与一键启用，不会阻止游戏加载。

## 文件操作

文件操作分为单文件菜单和多文件菜单。单文件菜单用于处理当前 Mod，多文件菜单用于处理已经勾选的一组 Mod。

## 单文件菜单

在列表或卡片中点击单个 Mod 的“更多操作”，或对单个 Mod 打开右键菜单，可以使用以下功能：

- 详情：查看 Mod 标题、文件信息、标签、预览图和解析到的内容。
- 启用 / 禁用：把当前 Mod 加入或移出游戏加载范围。位于 `workshop` 的文件会显示“转移”，用于移动到可管理目录。
- 跳转工坊：有工坊 ID 的 Mod 可以直接打开对应的创意工坊页面。
- 分享物品：复制当前 Mod 的工坊信息，方便发给别人。
- 设置标签：编辑一级标签和二级标签，用于筛选、整理和批量管理。
- 上传服务器：已配置服务器面板时，可以把当前文件上传到指定服务器。
- 重命名：修改 VPK 文件名，便于本地识别。
- 加载顺序：调整当前 VPK 的加载顺序，处理资源覆盖优先级。
- 解包：把 VPK 解包到文件夹，适合查看或修改资源。
- 打开位置：在资源管理器中打开文件所在目录。
- 隐藏 / 取消隐藏：把暂时不想看到的 Mod 从默认列表里隐藏，开启“显示隐藏”后可找回。
- 删除：把文件移动到回收站。

## 多文件菜单

勾选多个 Mod 后，可以使用底部批量按钮或右键菜单处理选中文件：

- 全选 / 取消全选：快速调整当前列表中的选择范围。
- 游戏内启用 / 游戏内关闭：把选中的 Mod **设为游戏内开启或关闭** —— 只写 `addonlist.txt` 的 `0/1`，
  **不移动、不删除任何文件**；未记录在 `addonlist.txt` 的条目会按「未记录 Mod 插入位置」设置写入，
  已在目标状态的会跳过，`disabled` 目录里的会被跳过（要改游戏开关得先用下面那组放回 addons）。
  后端是一次加锁、一次写盘（`SetVPKGameEnabledBatch`），几百个一起改也很快；
  策略组开了「自动联动」时照常联动，提示里会写"并按策略组自动联动另外 N 个"。
- 批量启用 / 批量禁用：在 `addons` 与 `disabled` 目录之间**搬文件**（这会改变 Steam/游戏能否看到它）。
  下拉菜单里还可以执行“禁用全部 Mod”“禁用全部人物 Mod”“禁用全部武器 Mod”。

> 两组的区别就是"改开关"还是"搬文件"：
> **游戏内开/关** = 游戏读 `addonlist.txt` 时的 `0/1`；**批量启用/禁用** = 文件在不在 `addons` 里。
- 批量隐藏 / 批量取消隐藏：一次隐藏或恢复多个 Mod。
- 分享物品：批量复制选中 Mod 的工坊信息；没有工坊 ID 的文件会被跳过。
- 设置标签：给多个 Mod 统一设置一级标签和二级标签。
- 上传服务器：已配置服务器面板时，把选中的多个文件加入上传任务。
- 导出 ZIP：把选中文件打包导出，适合向其他玩家分享地图和 Mod。
- 移动文件：把选中文件移动到指定目录。
- 批量删除：把选中文件移动到回收站。

批量操作前请先确认底部状态栏里的“已选择”数量，避免误操作不相关文件。
删除和移动会改变磁盘上的真实文件，执行前请确认目标文件。

## 常见问题

### 扫描不到 Mod 怎么办？

先确认选择的是 L4D2 的 `left4dead2/addons` 目录，而不是游戏根目录或 `workshop` 上级目录。

可以尝试：

- 点“刷新”重新扫描。
- 检查文件扩展名是否为 `.vpk`。
- 确认文件没有被系统隐藏或移动到其他目录。

### 有没有预设功能？

可以。“设置 → 游戏配置 → 启用方案”支持把当前的启用组合与加载顺序保存成命名方案，一键切换，也可以导出分享给他人。

如果需要的是“按主题临时挑一批 Mod”，仍然可以用“二级标签”配合批量开关：把一组想同时启用或禁用的 Mod 都设置为相同的二级标签，例如 `写实包`、`娱乐包`、`战役合集`，之后在 MOD 管理页用子标签筛选出这一组 Mod，再全选并批量启用或批量禁用。

### 为什么 Mod 下载后保存的文件名是 `id.vpk`？

因为 Windows 对文件路径长度有限制，不同玩家的游戏安装路径也不同。如果直接使用 Mod 名称作为文件名，有时路径会过长，导致游戏无法读取文件。

如果你希望文件名更容易识别，可以在重命名弹框中选择按 Mod 名称重命名。

### 误删或误移动文件怎么办？

删除和移动是真实文件操作。执行前请确认选中文件和目标目录。

如果担心误操作，建议先使用“导出 ZIP”备份一批重要 Mod。删除操作会移动到回收站，可以先在回收站中查找。
