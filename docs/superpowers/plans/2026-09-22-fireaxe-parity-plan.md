# FireAxe 能力补齐执行计划

> 对照基线：ktxiaok/FireAxe `f8aa1cf1391802c64525412fdf326dbe0ecc98b1`（v0.7.3，Apache-2.0）。
>
> **原则**：只补 FireAxe 的强项，不牺牲 LytVPK 已有优势——直接管理真实文件、
> addonlist 全生命周期（编码保真 / 原子写 / 多类型备份 / 运行时监控恢复）、
> 冲突严重度分级与可组合基线、工坊链路（翻译 / IP 优选 / 分块下载 / 转移 / 更新检测）、
> 服务器面板与工具箱（打包解包 / 完整性修复 / 模型统计 / 喷漆 / mdmp / autoexec）、
> 体检与报告导出。任何改动都不得让上述能力退化。

## 交付顺序

| # | 功能 | 价值 | 成本 | 依赖 |
| --- | --- | --- | --- | --- |
| 1 | 统一优先级模型（分层 + 组权重） | 高 | 中 | 设计见 `2026-09-22-unified-priority-model-design.md` |
| 2 | 每 Mod 冲突忽略文件 | 高 | 低 | 无 |
| 3 | 本地记录备份轮转 | 中 | 低 | 复用 addonlist 备份思路 |
| 4 | 变更驱动的自动复检 | 中 | 中 | 依赖 #1、#2 的判定结果 |
| 5 | 游戏原版文件白名单（分批） | 高 | 中 | 需数据校验流程 |
| 6 | 自动重下策略 | 低 | 低 | 复用下载队列 |
| 7 | 合集实体化 | 中 | 中 | 依赖已有的嵌套合集解析 |
| 8 | 树形分组 / 嵌套层级 | 高 | 高 | 前端列表重构，最后做 |
| 9 | i18n（先抽文案层） | 中 | 高 | 文案量大 |
| 10 | 自身崩溃上报 | 中 | 中 | 与 mdmp 查看器互补 |

**有意不补**：符号链接 push（与真实文件管理模型冲突）、`RefAddonNode`（已由启用方案覆盖）、
把优先级做成独立于 addonlist 的平行状态（见优先级设计文档的取舍说明）。

## Task 1：统一优先级模型

- 代码落点：`internal/app/priority.go`（新）、`conflict.go`（判定切换）、
  `addon_list_load_order.go`（排序接入）、`mod_groups.go`（组 `Tier *int`）。
- 关键约束：未分层时行为逐字节不变（黄金回归测试守住）；只有显式"应用分层"才重排。
- 前端：列表与冲突卡片显示 `优先级 #顺序（分层 T）`；加载顺序弹窗支持设置分层与组权重。

## Task 2：每 Mod 冲突忽略文件

- 存储：`ignore.json`（键 = addonlist 键，值 = 路径列表），与 dependencies 同级。
- API：`GetModIgnoreFiles(key)` / `SetModIgnoreFiles(key, paths)`。
- 判定：内置规则 ∪ 全局清单 ∪ 该 Mod 自己的清单（并集）。
- 前端：Mod 详情增加"该 Mod 的忽略文件"编辑器；冲突结果标注被自身规则忽略的项。
- 测试：单 Mod 规则只影响该 Mod 参与的重叠，不影响其它 Mod 之间的判定。

## Task 3：本地记录备份轮转

- 对象：`profiles.json` / `groups.json` / `dependencies.json` / `ignore.json` / `priority.json`。
- 策略（对齐 FireAxe `BackUpIfNeed`）：最短间隔 + 与上一份内容相同则跳过 + 数量上限 + 溢出进回收站。
- 落点：`internal/app/local_store_backup.go`，被各 store 的写入路径统一调用。

## Task 4：变更驱动自动复检

- 触发点：`SetVPKGameEnabled`、方案应用、策略组应用、依赖启用、文件移动/删除之后。
- 行为：只重算受影响条目（复用 `conflictIndexCache` 与 addonlist 状态映射），
  结果进内存缓存供列表角标展示；**不自动改文件**，修复仍需用户确认。
- 测试：状态变化后缓存标记为脏并按需重算；无变化时不重复扫描。

## Task 5：游戏原版文件白名单

- 形式：`assets/stock-files/*.txt`（每行一个路径，可分批增量），只用于忽略、不改写任何文件。
- 降级：白名单缺失或解析失败时退化为当前内置规则，不阻断冲突检测。

## Task 6-10 概要

- **自动重下策略**：下载任务增加 `autoRedownload`（默认关），失败或检测到更新后自动重试一次。
- **合集实体化**：新增"工坊合集"条目类型，保存合集 ID 与展开结果，下载/更新跟随节点。
- **树形分组**：先做数据层（父子关系 + 组权重），再做 UI；必须保留现有扁平视图为默认。
- **i18n**：先抽 `messages/zh-CN.json` 文案层保证行为不变，再逐页迁移，最后加语言切换。
- **崩溃上报**：捕获 panic/未处理异常 → 本地报告（版本、日志尾部、可选 mdmp），复用 mdmp 工具查看。

## 验证与收口标准

**自动化优先，人工项不阻塞**：

1. 能自动化的验证一律自动化：Go 端到端（临时目录造真实 VPK + addonlist fixture 直接调用导出的
   App 方法）、前端纯函数 `node --test`、可用的 DOM/无头浏览器检查、
   `go test ./...` / `node --test` / `npm run build` / `wails build` / `npm run docs:build`。
2. 新增 Go 导出方法后必须 `wails generate module`，并确认 `models.ts` / `App.d.ts` 出现对应导出。
3. 需要网络的能力（工坊接口）优先改成可注入 fetcher 并 mock 测纯逻辑。
4. 只有确实无法自动化的（真实游戏内加载顺序、真实工坊链接、纯视觉判断）才写入
   `docs/development/manual-verification.md` 的"待人工验证"小节，然后继续推进其它任务，
   **不得因此停下或宣布整项阻塞**。
5. 每条结论必须标注证据等级：已自动验证 / 只能人工验证 / 仍未验证；
   严禁把"构建通过、绑定存在、配置写对"当作"功能已验证"。

**每项收口**：先失败测试 → 实现 → 全量验证 → 同步 `docs/`（功能文档 + 手工验证清单）。
