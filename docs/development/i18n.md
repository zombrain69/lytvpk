# 文案层（i18n）维护说明

> 目标：把界面文案从代码里抽出来，最终支持语言切换。
> 当前状态：**运行时 + 文案目录已就绪**；页面按下面的约定逐页迁移
> （完成进度见「已迁移页面」与 CHANGELOG）；未迁移的页面保持中文字面量，行为不变。

## 文件与职责

| 文件 | 职责 |
| --- | --- |
| `frontend/src/messages/zh-CN.json` | 中文文案目录（唯一事实来源） |
| `frontend/src/js/core/i18n.mjs` | 纯函数：取 key、回退、参数插值、语言切换（`node --test` 覆盖） |
| `frontend/src/js/core/i18n-runtime.js` | 运行时：`t()` / `setLocale()` / `applyTranslations()` / `installCatalogs()`（多目录）/ `installCatalog()`（单目录兼容入口）；**不 import JSON**，Node 可直接导入 |
| `frontend/src/js/core/i18n-setup.js` | 浏览器入口接线：把**全部随包目录**（zh-CN + en）一次装进运行时（`main.js` 最先导入） |
| `frontend/src/messages/en.json` | 英文目录（第 19 项 P2 全量产出前的**渐进占位**：只放已翻译 key，缺翻自动回退中文） |
| `frontend/src/js/core/locale.mjs` | locale 纯逻辑：白名单归一化（`zh-CN` / `en`，与后端 `normalizeLocaleKey` 同套）、语言自称、入口开关 `LANGUAGE_SWITCH_ENABLED` |
| `frontend/src/js/core/i18n-test-catalog.mjs` | 仅供 `node --test`：把真实目录装进运行时（`installTestCatalog()`），纯模块单测断言中文文案用 |

为什么 runtime 与目录装配分成两个文件：JSON 模块的 import 属性语法
（`with { type: "json" }`）只有 Node 认识（并已成为必需的），而 Rollup 2 / Vite 3
的构建不认（实测 `Unexpected token` 直接构建失败）；不写属性则 Node 导入报错。
「纯模块（有 node 单测的 `.mjs`）直接 import `i18n-runtime.js` 用 `t()`」与
「浏览器构建」因此只能靠拆分文件两全：runtime 干净、JSON 只留在 setup 里。
纯模块的单测要用真实中文目录时，先调用 `installTestCatalog()` 再断言。

## key 命名

按页面 → 区域 → 名称分组，全部小写驼峰：

```
toolbox.title
toolbox.section.diagnostics.title
toolbox.card.conflictCheck.action
```

规则：

- 动作用 `action`，说明用 `description`，状态用 `status`；
- 不要在一个 key 里塞多种含义，宁可多写一条；
- 参数用 `{name}` 占位：`"共 {count} 个工具"`。

## 迁移一页的步骤

1. 在 `messages/zh-CN.json` 增加该页面的 key；
2. 页面里 `import { t } from "../../core/i18n-runtime.js"`，把中文字面量换成 `t("...")`；
3. 静态 HTML 节点可以直接写 `data-i18n="key"`（标题用 `data-i18n-title`，
   输入框占位符用 `data-i18n-placeholder`），在页面渲染后调用 `applyTranslations()`；
4. 跑 `node --test` 与 `npm run build`；
5. 在 `docs/development/manual-verification.md` 里更新该页面的迁移状态。

- **缺失 key 返回 key 本身**，不会抛错、不会渲染成空白；因此迁移可以逐页进行，
  中途状态始终可用。
- 只有 `zh-CN` 一个目录时，`t()` 的行为与直接写中文字面量完全一致。

## 第二语言（en）与界面语言（locale）

> 路线图第 19 项；拆包与决策见 `i18n-language-switch-eval.md`。P0（2026-10-12）：

- **装载**：`i18n-setup.js` 用 `installCatalogs({ "zh-CN": zhCN, en }, "zh-CN")` 一次装齐；
  运行时的回退链是「当前语言 → zh-CN → key 本身」。
- **en 目录（P2 已全量，2026-10-12）**：3750/3750 键全量机翻产出（分块批次 + 术语表 + 占位符/key
  校验 + 中文残渣扫描；键序与 `zh-CN.json` 保持子序列关系）。维护规则不变：zh 新增 key 后 en
  暂时缺翻 → 运行时回退中文；补齐时沿用同一流水线。别写空字符串当占位——空串是合法值，
  会遮住回退链（渲染成空白）。
- **有意保持原文（verbatim 白名单）**：`messages/en-verbatim-allowlist.json` 列出「值必须与 zh
  完全一致」的 key —— 目前是 4 个搜索语法示例值（承载解析器数据层标签名，如 `tag:步枪`；标签值
  不做映射层是 2026-10-12 的既定决策）。一致性测试只对这些 key 放行 CJK，并要求与 zh 逐字一致。
- **切换收尾（P2）**：卡片渲染签名纳入界面语言（`file-list/render.js` 的
  `getFileCardRenderSignature`），否则语言切换后卡片会被整批复用、旧语言文案停在屏幕上；
  一次性填充 / 状态驱动的浮层与状态面（搜索说明书、快捷键总览、冲突与策略组弹窗、分组筛选、
  轮换按钮、分类侧边栏）在 `app:locale-change` 时就地重建。块级页面仍按「访问/重开生效」。
- **一致性测试**（`i18n-catalog.test.mjs`）：en 的每个 key 必须在 zh-CN 中存在、
  `{placeholder}` 集合与 zh 一致、值非空且无中文残渣（CJK），并有规模下限兜底。
- **locale 持久化**：`config.json` 的 `locale`（`zh-CN` / `en`）；双端白名单
  `frontend/src/js/core/locale.mjs` ↔ `internal/app/config.go` 的 `normalizeLocaleKey`
  必须同套取值（前端 `language-settings.test.mjs` 有跨端断言），未知值一律回落 `zh-CN`。
  启动时在 `initConfig()` 之后、首帧渲染之前 `setLocale(...)`（`app-runtime.js` 的
  `initializeApp`）。
- **切换语义（P1 已落地，2026-10-12）**：立即生效 = ①静态节点全量重放（`applyTranslations`，
  与启动共用一条路径）+ ②`setLocale` 在语言真正变化时派发 `app:locale-change`，各页面模块
  按自己的入口重画动态面。重绘只接「没有重进自愈路径、可能以旧语言被看到」的面：
  - mods 默认页：`filters.js`（列表/命中计数 = `performSearch`、标签条 = `renderTagFilters`、
    排序按钮 = `updateSortButtonUI`）+ `directory-dropdown.js`（目录下拉）；
  - 工坊页：`app-init.js`（侧边分类 = `renderWorkshopSidebar` + 缓存卡片 =
    `rerenderWorkshopBrowserFromCache`，后者不触发网络请求）；
  - 设置页：`app-runtime.js`（整页重画 + 保持当前分区；用户就站在这一页上切换）。
  其余页（下载/服务器/工具箱/关于）每次进入都由 `app:page-change` 整页重建，不会以旧语言
  被看到，故**不**接 `app:locale-change`（避免切换语言时触发后端/网络查询）。
  打开中的弹窗 / toast 维持「重开生效」；启动应用持久化语言走 `{ notify: false }` 静默
  （首帧渲染前各页按当前语言首渲染）。契约测试：`features/locale-change-wiring.test.mjs`
  （接线）+ `core/i18n-runtime.test.mjs`（派发行为）。
- **入口开关**：设置页「界面」panel 的语言行由 `LANGUAGE_SWITCH_ENABLED`
  （`core/locale.mjs`）控制；P0–P2 保持 `false`（隐藏）——P2 全量产出与切换收尾已落地，
  待 P3（本地化排序 / 长文本溢出）与 en 人工审校归档后翻 true（翻 true 是唯一改动点；
  行渲染与切换处理已经接线并有测试兜底）。
