# 文案层（i18n）维护说明

> 目标：把界面文案从代码里抽出来，最终支持语言切换。
> 当前状态：**运行时 + 文案目录已就绪**；页面按下面的约定逐页迁移
> （完成进度见「已迁移页面」与 CHANGELOG）；未迁移的页面保持中文字面量，行为不变。

## 文件与职责

| 文件 | 职责 |
| --- | --- |
| `frontend/src/messages/zh-CN.json` | 中文文案目录（唯一事实来源） |
| `frontend/src/js/core/i18n.mjs` | 纯函数：取 key、回退、参数插值、语言切换（`node --test` 覆盖） |
| `frontend/src/js/core/i18n-runtime.js` | 运行时：`t()` / `setLocale()` / `applyTranslations()` / `installCatalog()`；**不 import JSON**，Node 可直接导入 |
| `frontend/src/js/core/i18n-setup.js` | 浏览器入口接线：把 `zh-CN.json` 装进运行时（`main.js` 最先导入） |
| `frontend/src/js/core/i18n-test-catalog.mjs` | 仅供 `node --test`：把真实目录装进运行时（`installTestCatalog()`），纯模块单测断言中文文案用 |

为什么 runtime 与目录装配分成两个文件：JSON 模块的 import 属性语法
（`with { type: "json" }`）只有 Node 认识（并已成为必需的），而 Rollup 2 / Vite 3
的构建不认（实测 `Unexpected token` 直接构建失败）；不写属性则 Node 导入报错。
「纯模块（有 node 单测的 `.mjs`）直接 import `i18n-runtime.js` 用 `t()`」与
「浏览器构建」因此只能靠拆分文件两全：runtime 干净、JSON 只留在 setup 里。
纯模块的单测要用真实中文目录时，先调用 `installTestCatalog()` 再断言。

## key 命名

按页面 → 区域 → 名称分组，全部小写驼峰：

```
toolbox.title
toolbox.section.diagnostics.title
toolbox.card.conflictCheck.action
```

规则：

- 动作用 `action`，说明用 `description`，状态用 `status`；
- 不要在一个 key 里塞多种含义，宁可多写一条；
- 参数用 `{name}` 占位：`"共 {count} 个工具"`。

## 迁移一页的步骤

1. 在 `messages/zh-CN.json` 增加该页面的 key；
2. 页面里 `import { t } from "../../core/i18n-runtime.js"`，把中文字面量换成 `t("...")`；
3. 静态 HTML 节点可以直接写 `data-i18n="key"`（标题用 `data-i18n-title`，
   输入框占位符用 `data-i18n-placeholder`），在页面渲染后调用 `applyTranslations()`；
4. 跑 `node --test` 与 `npm run build`；
5. 在 `docs/development/manual-verification.md` 里更新该页面的迁移状态。

## 行为保证

- **缺失 key 返回 key 本身**，不会抛错、不会渲染成空白；因此迁移可以逐页进行，
  中途状态始终可用。
- 只有 `zh-CN` 一个目录时，`t()` 的行为与直接写中文字面量完全一致。
- 语言切换（`setLocale`）已经实现，但要等所有页面迁移完再暴露入口，
  避免出现"一半中文一半英文"的界面。

## 一致性检查

`frontend/src/js/core/i18n-catalog.test.mjs`：页面代码里 `t("...")` 引用的每个 key
都必须存在于 `messages/zh-CN.json` —— 迁移时"接好线、忘加文案"会静默渲染成 key 本身，
由这条测试兜住。同一测试还做反向检查：`index.html` 静态节点上 `data-i18n` /
`data-i18n-title` / `data-i18n-placeholder` 引用的 key 也必须存在（静态节点写错 key
与页面 `t()` 漏配文案是同一类静默失效）。
