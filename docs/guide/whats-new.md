# 本 Fork 新增功能一览（入口 + 用法）

这一页只讲 `zombrain69/lytvpk` Community Fork **相对上游新增或显著强化**的部分：
每一项都写明「在界面哪里进」和「大概怎么用」。上游已有的基础功能请对照上游文档，这里不重复。

> 忘了按钮在哪？按 `Ctrl + K` 打开**命令面板**，输入关键词（如"体检""分组""分层"）直接跳；
> 按 `?` 可以打开**快捷键总览**。

## 一、先记住三个万能入口

| 入口 | 位置 | 用途 |
| --- | --- | --- |
| 命令面板 | `Ctrl + K`（或标题栏的闪电图标） | 搜页面名 / 功能名 / 常用动作，回车执行；会记住最近用过的命令 |
| 快捷键总览 | 标题栏 `?` 按钮，或直接按 `?` | 列出全部键位；输入框里按 `?` 不会触发 |
| 设置页 | 左侧导航「设置」 | 分四个面板：**网络设置 / 界面设置 / 工坊设置 / 游戏配置** |

左侧导航一共八个页面：**MOD 管理 / 创意工坊 / 下载与解析 / 收藏服务器 / 工具箱 / 设置 / 使用说明 / 关于**。

## 二、优先级与加载顺序（统一优先级模型）

**做什么**：给 Mod 一个"想让谁覆盖谁"的**显式分层**，加上策略组的**组权重**，渲染成同一个"有效分层"，
同时用于列表排序、冲突判定和写回 `addonlist.txt`。

| 功能 | 入口 |
| --- | --- |
| 设置单个 / 一批 Mod 的分层 | 「MOD 管理」工具栏 → **加载顺序** → 窗口里的「优先级分层（可选）」 |
| 微调顺序 | 同窗口的「上移一位（优先级更高）」「下移一位（优先级更低）」或直接填「新序号」 |
| 按分层重排游戏内顺序 | 同窗口底部 → **按分层应用** |
| 按优先级编号定位 | 工具栏「优先级 #」输入框 + **定位**（任意排序方式下都能定位） |
| 按"有效分层"看列表 | 工具栏排序菜单 → **优先级排序（分层优先，其次加载顺序）**；每行角标显示 `优先级 #N` |

**怎么用（典型流程）**

1. 勾选要调整的 Mod（可多选），点工具栏「加载顺序」。
2. 在「优先级分层（可选）」里填数字：**数值越小越先加载**（更容易被后面的覆盖）。
3. 需要时用上移/下移按钮或「新序号」微调相对位置。
4. 点 **按分层应用** —— 只有点了它才会真正重排 `addonlist.txt`。
5. 切到「优先级排序」，用角标确认结果。

**要点**：没设置过分层时，一切都和以前一样（写盘内容逐字节不变，有黄金回归测试守着）；
`addonlist.txt` 的顺序仍然是游戏侧唯一权威，分层只是"意图 + 判定 + 排序"层；写盘走整批事务，
失败会回滚到写之前的一致状态。

## 三、策略组（分组管理全生命周期）

**做什么**：把"一组要么全开、要么只开一个"的 Mod 归成一个组，支持层级、权重、拖放、批量操作，
并能在主列表里按组筛选。

| 你要做的事 | 入口 |
| --- | --- |
| 把勾选的 Mod 建成新组 | 工具栏 **全部分组** → 「用选中的 Mod 建组」 |
| 打开管理窗口 | 工具栏 **全部分组** → 「策略组管理…」 |
| 按组筛选主列表 | 工具栏 **全部分组** → 下半部分的组列表（可多选）；筛选顺序按组权重排，子组跟在父组下面 |
| 在组之间搬运 Mod | 勾选 Mod → 用「加入组」类的按钮；或打开管理窗口展开成员后逐条操作 |

**管理窗口里能做什么**

- **应用策略**：组内策略有四档 —— 全部开启 / 全部关闭 / 互斥单选 / 随机单选；点应用前会先做
  **可满足性预检**（空组、成员全丢、全在 `disabled` 之类会直接拦下并说明原因）。
- **组权重**：每行可填「权重」，数值越小越先加载；组权重按**祖先链累加**，跨链取 `min`。
- **层级**：每行有「＋ 子组」和「上级分组」下拉；也可以直接把行**拖到**另一行上（放进组里 / 排前 / 排后 / 回到顶层），
  超过 4 层或成环会被拒绝。
- **批量操作**：勾选多个组后可以「批量删除」「开启/关闭自动联动」「设置权重 / 清除权重」「用选中的组筛选」。
- **展开成员**：展开后可直接看详情、改游戏内开关、启用/禁用、复制到 addons、把单个 Mod 移出本组。
- **搜索**：支持与其他面板同一套语法（`-排除`、`re:` 正则、`tag:状态`）。

**删除组会发生什么**：组成员不会被动到；列表里会显示为"缺失成员"，把同名文件放回来就会自动重新回到组里。

## 四、分组建议（含外部智能体流程）

**做什么**：自动推导"可能属于同一组"的 Mod；也可以把材料交给大模型 / 外部脚本分析，
再把结果**导回**应用。

| 按钮 | 作用 |
| --- | --- |
| 重新推导 | 用内置规则（工坊合集、文件名前缀、共同标签、同一作者、相同主体、动作/换装槽位等）重新算一遍 |
| 导出 Mod 清单… | 先重扫一遍目录，再导出完整清单（键、标题、作者、标签、主体、语音角色、结构提示等） |
| 准备给智能体的材料 | 一步到位：重扫 → 导出清单 → 复制填好路径的提示词 |
| 编辑提示词… | 改这套提示词（默认是内置的一套，可恢复默认） |
| 导入建议文件… | 导入标准格式的建议 JSON，逐条选择采纳 |

**入口**：工具栏 **全部分组** → 「分组建议」。

**推荐流程**

1. 点「准备给智能体的材料」，按提示把文件与提示词交给智能体。
2. 智能体产出标准建议文件（含组名、成员、策略、置信度、标签等）。
3. 回到窗口点「导入建议文件…」，在收件箱里按**置信度筛选 / 标题搜索**，点开卡片看详情后决定采纳哪些。
4. 采纳后的组和手工建的组一样，可以在「策略组管理」里继续调权重、层级、策略。

详见 [分组建议与外部导入](/features/group-suggestion-import)。

## 五、冲突分析、忽略清单与自动复检

| 功能 | 入口 |
| --- | --- |
| 开关冲突分析 | 「MOD 管理」工具栏 → **冲突分析** |
| 选择对比范围 / 条件组合 | 工具栏 → **对比范围** |
| 完整冲突检测 | 工具箱 → **Mod 冲突检测** → 开始检测 |
| 全局忽略清单 | 设置 → 游戏配置 → **Mod 冲突分析** |
| 单个 Mod 的忽略清单 | 列表行「详情」→ **该 Mod 的冲突忽略文件** → 填写 → 保存忽略清单 |
| 看某个 Mod 的冲突 | 行内冲突角标（点击查看覆盖关系与风险分级） |

**要点**：忽略集合是 **内置规则 ∪ 全局清单 ∪ 单 Mod 清单**；冲突只在**同一有效分层**内判为真冲突，
其余算覆盖关系；严重程度分级（critical / warning / info）与可组合基线是本 Fork 的既有优势。
关掉开关、启用禁用、改文件名等状态变化后会自动让相关结果失效并**按需重算**，
列表角标会跟着更新，不用手动重新扫。

## 六、Mod 体检与一键修复

**入口**：设置 → 游戏配置 → **Mod 体检** → 「开始体检」。

体检报告里可以做的事：

- **检索**：报告结果支持与其它面板同一套搜索语法（含 `tag:` 状态过滤），大报告也能快速定位。
- **一键修复（白名单）**：重复条目、缺失条目、依赖未开启这几类带「修复」按钮，
  修复前会先做 `before-…` 备份，并且在 `addonlist.txt` 事务里写盘。
- **导出**：支持把报告另存为 Markdown 文件。

新增的诊断类型（以前会漏报或误报的情况）：

| 诊断 | 说明 |
| --- | --- |
| 工坊作品有多份副本 | `addons\<ID>.vpk` 与 `addons\workshop\<ID>.vpk` 同时存在时提示（只提示，删除由你决定） |
| 文件类型不符 | `addonlist.txt` 里记录的是同名**文件夹**而不是 VPK |
| 工坊记录身份不一致 | `workshop\<ID>.meta` 里的作品 ID 与文件名对不上（更新检测会拿错时间戳） |
| 条目在受管目录之外 | `addonlist.txt` 解析到 addons / workshop / disabled 之外 |
| 依赖成环 | 依赖链出现环（报告里会写出完整链路 `甲 → 乙 → 甲`） |

详见 [Mod 体检](/toolbox/mod-health-check)。

## 七、启用方案与 Mod 依赖

**入口**：设置 → 游戏配置 → **启用方案** / **Mod 依赖**。

- **启用方案**：把当前"哪些开、哪些关 + 分层"存成一套方案，之后一键切回；
  支持含自动化信息的捕获、应用、导出与导入。
- **Mod 依赖**：声明"开 A 必须先开 B"；体检会报"依赖未开启"并给出一键启用；
  成环会被检测出来。

## 八、工坊链路（标签 / 合集 / 翻译 / 剪贴板识别）

| 功能 | 入口 |
| --- | --- |
| 浏览、搜索、看详情、翻译描述 | 左侧导航 **创意工坊** |
| 下载 / 解析链接 | 左侧导航 **下载与解析**（也支持拖拽链接、粘贴按钮） |
| 官方标签与统计抓取 | 设置 → 工坊设置 → **抓取工坊官方标签与统计**（写进 `.meta` 的 `steam_tags` 等字段） |
| 工坊合集 | 设置 → 工坊设置 → **工坊合集** 卡片（抓取 / 刷新 / 补下缺失成员 / 检查更新） |
| 浏览器跳转目标 | 设置 → 工坊设置 → **浏览器跳转**（镜像 / 官方） |
| 描述翻译服务 | 设置 → 工坊设置 → **描述翻译**（内置 / 自定义接口） |
| 剪贴板工坊链接自动识别 | 设置 → 工坊设置 → **剪贴板工坊链接自动识别**（默认开启，可关） |

**剪贴板识别怎么用**：复制一条创意工坊链接（或纯作品 ID）→ 切回 LytVPK →
会弹确认框问是否打开下载页并解析。窗口不在前台时不会读剪贴板，同一条链接不会反复打扰。

## 九、下载（暂停 / 续传 / 自动重下）

| 功能 | 入口 |
| --- | --- |
| 任务列表（进度、暂停、继续、重试、清除已完成） | 左侧导航 **下载与解析** 的任务列表 |
| 失败自动重下一次（默认关闭） | 设置 → 工坊设置 → **下载失败后自动重下一次**；也可在任务行单独开关 |
| 优选 IP / 固定 IP | 设置 → 网络设置；下载链接里含 `cdn.steamusercontent.com` 时还能临时勾选 |

**断点续传**：按区块记录检查点，暂停 / 失败 / 重启后可以接着下；进度快照按 1 秒节流写盘，
重启后未完成的任务会显示为「已中断」并可一键重试。

## 十一、收藏服务器与服务器面板

**入口**：左侧导航 **收藏服务器** → 在收藏 / 最近列表里对某个服务器打开「面板详情」窗口 →
顶部按钮 **刷新状态 / 地图 / RCON / 打开面板**。

「打开面板」会进入完整服务器面板：看资源占用、改难度、管理地图、上传地图文件、
发送 RCON 指令、热重载地图，并跟踪上传任务进度；「地图」和「RCON」按钮可以直接跳到对应区块。
服务器查询走 A2S 协议，支持收藏与最近访问列表。

## 十二、检索体验

**同一套语法，覆盖 6 个面板**（Mod 列表、冲突弹窗、体检结果、归档管理、模型统计、策略组管理）：

| 写法 | 含义 |
| --- | --- |
| `ak47 m16` | 多个词按"且"匹配 |
| `-材质` | 排除包含该词的结果 |
| `tag:武器` / `tag:武器|角色` | 按标签（或）匹配 |
| `re:^ak` | 正则匹配 |
| `"精确短语"` | 带空格的短语 |

另外：搜索结果可以用 `↑` `↓` 移动**键盘光标**、回车打开详情、`Esc` 清空并复位；
搜索框旁边的 `?` 会打开**语法说明书**（与快捷键总览同一份来源）。

> 注意：**创意工坊浏览器**的搜索框是"服务端搜索"，只能用关键词，不支持 `tag:` / `re:`（界面里已写明原因）。

## 十四、稳定性、数据安全与发布

- **`addonlist.txt` 全生命周期**：快照备份、手动备份、恢复、删除；可启用运行时保护，
  检测到外部覆盖后先保存外部版本再原子恢复；编码 / BOM / 换行保真。
- **本地记录备份轮转**：`profiles.json` / `groups.json` / `dependencies.json` / `ignore.json` / `priority.json`
  都会按"最短间隔 + 内容相同跳过 + 数量上限"轮转，溢出进回收站；这几个文件都带
  `schemaVersion`，旧版本会被迁移，坏值会被读时修正。
- **路径守卫**：删除 / 移动 / 改名的**源文件**必须在 addons / workshop / disabled 之内
  （"移动到用户自选目录"仍然允许）。
- **文件操作互斥**：移动 / 删除 / 打包同一时间只允许一个，忙碌状态会显示在界面上；
  批量操作的失败原因会逐项列出（前 3 条 + "另有 N 条"，控制台保留全量）。
- **崩溃上报**：程序自身崩溃会在「关于」页列出报告（含版本与日志尾部），可与工具箱的 `.mdmp` 查看器配合。
- **游戏目录自动探测**：注册表 → `libraryfolders.vdf` → 盘符兜底。
- **更新源固定本 Fork**：只检查 `zombrain69/lytvpk` 的 Release，不回退到上游。

## 十五、自定义外部打开程序

**入口**：设置 → 界面设置 → **打开文件方式（可选）**。

- **留空 = 系统默认**（Windows 用资源管理器定位并选中文件，行为与以前完全一致）。
- 填了「程序」后，"打开所在位置"就交给它。参数模板占位符：
  `{path}`（完整路径）、`{dir}`（所在目录）、`{name}`（文件名），也兼容 FireAxe 的 `{0}`；
  模板里没有占位符时，会自动把完整路径追加到末尾。
- 例：Total Commander 定位 —— 程序 `C:\Tools\totalcmd\TOTALCMD64.EXE`，参数 `/O /T /L="{dir}"`。
- 只填命令名（如 `code`）交给 PATH 查找；填路径时会校验存在性；启动不经过命令行解释器。
