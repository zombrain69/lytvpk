# 为什么用这个 Fork：相对上游 lytvpk 与 FireAxe 的差别

这一页讲三件事：

1. 这个 Community Fork 相对**上游 LytVPK**（[LaoYutang/lytvpk](https://github.com/LaoYutang/lytvpk)）新增 / 强化了什么；
2. 相对 **[ktxiaok/FireAxe](https://github.com/ktxiaok/FireAxe)** 学到了什么，哪些地方做得更整合；
3. 各能力**互相咬合**带来的"1+1>2"效果 —— 这也是本 Fork 与"功能堆叠"最大的不同。

> 具体到"点哪个按钮、分几步"的完整地图见 [全功能地图](/guide/feature-tour)；
> 新增能力的教程见 [本 Fork 新增功能一览](/guide/whats-new)。

## 一、相对上游 LytVPK：新增与强化

上游已有的基础能力（目录切换、扫描、启用禁用、工坊浏览、下载、服务器查询、工具箱基础件）这里不重复列。
下面每一条都是上游**没有**或**明显更弱**的部分：

| # | 能力 | 上游 | 本 Fork |
| --- | --- | --- | --- |
| 1 | `addonlist.txt` 全生命周期 | 直接读写 | 快照备份 / 手动备份 / 恢复 / 删除 + **运行时保护**（检测到外部覆盖先保存外部版本再原子恢复）+ 编码 BOM 保真 + 写入事务回滚 + 与另一份 addonlist 的合并对比 |
| 2 | **统一优先级模型** | 无 | 显式**分层** + 策略组**组权重**（祖先累加、跨链 min）合成"有效分层"，列表排序 / 冲突判定 / 写盘三处共用同一套；只有点「按分层应用」才重排；未分层时行为逐字节不变 |
| 3 | 策略组 | 无 | 建组 / 策略（全部开启 · 全部关闭 · 互斥单选 · 随机单选）/ 应用前**可满足性预检** / 组权重 / 层级（最多 4 层）/ 拖放整理 / 批量删除与权重 / 展开成员直接操作 / 按组筛选（按权重排序） |
| 4 | 分组建议 + 外部智能体 | 无 | 内置规则推导（合集、前缀、标签、作者、主体、换装槽位）+ 「准备给智能体的材料」导出清单与提示词 + 标准建议文件导入 + 置信度筛选/搜索/卡片详情 |
| 5 | 冲突系统 | 简单覆盖提示 | **同层才算真冲突**、严重程度分级（critical / warning / info）、可组合基线、**内置 ∪ 全局 ∪ 单 Mod** 忽略清单、变更驱动自动复检、冲突弹窗统一检索 |
| 6 | Mod 体检 | 无 | 缺文件 / 重复条目 / 损坏 VPK / 类型不符 / 工坊记录不一致 / 越界条目 / 依赖成环与未开启；白名单一键修复（写前备份 + 事务写盘）+ 报告检索与 Markdown 导出 |
| 7 | 启用方案 / Mod 依赖 | 无 | 方案捕获（可含分层）· 应用 · 导出 · 导入；依赖声明 + 一键启用依赖 + 环检测 |
| 8 | 检索体验 | 各自一套 | **6 个面板同一套语法**（Mod 列表 / 冲突 / 体检 / 归档 / 模型统计 / 策略组）：多词且匹配、`-排除`、`tag:`、`re:`、引号短语；语法说明书与快捷键总览同源；结果键盘光标 + 命中高亮 |
| 9 | 界面与窗口 | 固定布局 | 界面缩放（80%–140%）、文字大小四档、阅读舒适度三档、**浮动窗口**（拖动/拉伸/点外部关闭/不虚化）、主窗口尺寸记忆、命令面板（`Ctrl+K`）、快捷键总览（`?`） |
| 10 | 工坊链路 | 浏览 + 下载 | **官方标签与统计抓取**（写进 `.meta` 的 `steam_tags` 等）、**工坊合集实体化**（记录 + 刷新 + 补下缺失 + 更新检查）、描述翻译、优选 IP、**下载暂停 / 断点续传**、进度落盘节流、任务去重、失败自动重下（默认关）、剪贴板链接自动识别 |
| 11 | 工具箱 | 基础件 | 8 件套整合：问题 Mod 查找、冲突检测、**Mod 体检**、模型面数、VPK 解包/打包、**完整性检测与安全修复**、**压缩包管理（ZIP/RAR/7Z/TAR 里识别 VPK 并对比）**、喷漆、autoexec 编辑器、mdmp 查看器 |
| 12 | 服务器 | 查询与加入 | **服务器面板**：资源状态、改难度、地图管理、**上传地图文件（带任务进度）**、RCON、**热重载地图** |
| 13 | 数据安全 | 有限 | 5 个本地记录文件**备份轮转**（最短间隔 + 内容相同跳过 + 上限 + 溢出进回收站）+ `schemaVersion` 迁移与读时自愈；**路径守卫**（源文件必须在受管目录内）；**文件操作互斥**；批量失败**逐项报告**；后台任务**失效目标守卫** |
| 14 | 崩溃排查 | 无 | 自身崩溃上报（版本 + 日志尾部，关于页可看）+ 工具箱 `.mdmp` 查看器互补 |
| 15 | 更新与发布 | 上游 Release | 更新源固定本 Fork、统一程序名与内容校验、发布包附源码/许可/修改说明 |

## 二、相对 FireAxe：学到了什么，哪里更整合

FireAxe 是另一套设计（C#/Avalonia、**符号链接 push** 到游戏目录、`.addonroot` 单存档、引用型节点 `RefAddonNode`、
Problem 体系、组树视图）。本项目按 Apache-2.0 只借鉴设计与算法，用 Go / 原生 JS 重写，并保留了"直接管理真实文件"的路线。

### 2.1 明确借鉴并已落地的（详见对照表）

| FireAxe 的设计 | 本项目的落地 |
| --- | --- |
| 显式优先级 + **层级累加** | 单 Mod 分层 + 组权重祖先累加，跨链取 `min` |
| 冲突只在**同优先级**内判定 | 同有效分层才算真冲突，其余按覆盖展示 |
| 忽略文件清单（内置 + 动态 provider 取并集） | 内置 ∪ 全局 ∪ 单 Mod |
| `BackUpIfNeed`（间隔 / 内容相同跳过 / 上限 / 回收站） | 5 个本地记录文件的备份轮转 |
| 组启用策略 + `CheckEnableStrategy` | 策略组四档 + 应用前**可满足性预检** |
| `Push()` 事务化（先算完整目标再落盘） | `runAddonListTransaction`：写盘 → 派生刷新 → 快照同步，失败回滚 |
| `.addonroot` 版本号 + 读旧版迁移 | 5 个 JSON 带 `schemaVersion` + 迁移器 + 读时自愈 |
| `DownloadService` 的暂停 / 续传 / 进度节流 | 区块检查点续传、1s 节流落盘、任务去重 |
| Problem 的"能不能自动修 / 该不该自动修" | 体检白名单一键修复（比上游更窄，必须用户确认） |
| 对象解释层（异常 → 人话） | 失败提示 + 灰按钮理由都给出"为什么 + 下一句怎么做" |
| 容器内名称唯一 / 子节点问题上报父节点 | 建组自动加序号、改名撞名报错；父组行显示子组缺失汇总 |
| 树视图拖放排序 | 组行拖放（放进组里 / 排前 / 排后 / 回顶层，拒绝成环与超层） |
| `GamePathUtils` 自动找游戏目录 | 注册表 → `libraryfolders.vdf` → 盘符兜底（多解析一层 Steam 库清单） |
| 路径合法性 / 根内约束 | `path_guard` + 体检 `outside_root` |
| `ValidRef` / `ValidTaskCreator`（失效引用守卫） | 后台任务写回前复查目标身份，被移动/替换就不写 |
| File Cleaner 的冗余 VPK | 体检项「工坊作品有多份副本」（只提示，删除由用户决定） |
| `F2` / `Delete` / `Ctrl+X`·`Ctrl+V` / 主窗口几何记忆 / 剪贴板识别 / 自定义外部打开程序 | 全部落地（详见 [新增功能一览](/guide/whats-new)） |

### 2.2 本项目更强或做了不同取舍的地方

| 维度 | FireAxe | 本 Fork |
| --- | --- | --- |
| 文件在哪 | 库目录 + **符号链接 push** 到游戏目录，等于两套真相 | **直接管理真实文件**：只有一份文件，改动立刻生效 |
| `addonlist.txt` | 重新写成 UTF-8 | 探测并保持**原编码 / BOM / 换行**，原子写 + 事务回滚 |
| 备份 | 备份自己的 `.addonroot` | 多类型备份（快照 / 手动 / 写前备份）+ **运行时监控恢复** |
| 冲突结论 | "同优先级即冲突" | **严重程度分级** + 可组合基线 + 忽略清单并集 |
| 搜索 | 一套搜索选项 | **6 个面板统一语法** + 语法说明书 + 键盘光标 + 命中高亮 |
| 界面 | 固定布局桌面窗口 | 浮动窗口 + 命令面板 + 快捷键总览 + 字号/对比度/缩放 |
| 策略组用起来 | 只能"应用策略" | 按组筛选主列表、整组平移（权重）、分组推导与外部导入、组内检索、展开成员直接开关 |
| 工坊链路 | 依赖 Steam 客户端回调 | 翻译 / IP 优选 / 分块下载 / 断点续传 / 转移到根目录 / 更新检测 / 合集实体化 |
| 附带工具 | 无 | 工具箱 8 件套 + **服务器面板**（地图 / 上传 / RCON / 难度 / 热重载） |
| 体检 | Problem 列表 | 体检 + **一键修复白名单** + 报告检索与导出 |
| 优先级状态 | 优先级存在自己的存档里 | 分层只是"意图 + 判定 + 排序"层，**`addonlist.txt` 顺序始终是游戏侧唯一权威** |

**有意不采纳**（都写过理由）：符号链接 push、`RefAddonNode`（同一 Mod 多组由"启用方案 + 策略组"覆盖）、
把优先级做成平行于 `addonlist` 的第二套状态、就地批量按作品标题改名（会破坏工坊 ID 与 `.meta` 配对）、
猜文件名式修复、空目录清理、自定义预览图的"第二套路径真相"。

## 三、整合点：为什么这些能力放在一起更好用

| 整合链 | 效果 |
| --- | --- |
| **组权重 → 有效分层 → 冲突判定 → 列表排序 → `addonlist.txt`** | 一个数字贯穿"意图 / 判定 / 排序 / 写盘"，不会出现"看到一套、判成另一套" |
| **标签 × 分组建议** | 标签已能表达的类型不必再建组（例如"全是替换 sg552 的枪"）；智能体在建议文件里产出的标签会写回标签体系，没产出时退回自动规则 |
| **分组建议 × 智能体材料 × 提示词编辑** | 导出清单已包含 VPK 结构、工坊官方标签、主体识别、套装线索，智能体不用自己拆包；产出走应用内 dry-run 校验后变成**可管理的组** |
| **体检 × 依赖 × 启用方案 × 事务写盘** | 体检发现问题 → 一键启用依赖（先备份）→ 事务写回 `addonlist.txt`，方案与快照同步更新 |
| **统一检索 × 6 个面板** | 学会一套语法，在列表 / 冲突 / 体检 / 归档 / 模型统计 / 策略组里通用 |
| **备份轮转 × schema 版本化 × 读时自愈** | 5 个本地记录都能安全升级；手改坏值会被修正而不是让界面崩 |
| **浮动窗口 × 命令面板 × 快捷键** | 边看主列表边管理组 / 顺序 / 冲突，不用来回切页面 |
| **路径守卫 × 文件操作互斥 × 失效目标守卫** | 批量移动/删除/打包不会互相插队，也不会写错位置 |
