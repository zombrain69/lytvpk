一个专为 Left 4 Dead 2 (L4D2) 设计的现代化 VPK 插件管理工具。
> 该项目通篇使用AI生成，本人只在AI陷入困境时进行少量修改。仔细阅读代码你就会发现大量无用变量、不符合规范的函数定义，一个文件几千行的屎山，均不代表本人水平，谢谢！

## 🆚 相对上游 LytVPK 与 FireAxe

**对比上游 LytVPK**（只列上游没有或明显更弱的部分）：`addonlist.txt` 全生命周期与运行时保护、
**统一优先级模型**（分层 + 组权重合成同一套"有效分层"，排序/判定/写盘共用）、策略组与分组建议、
冲突忽略清单与自动复检、Mod 体检与一键修复、启用方案与依赖、工具箱 8 件套、服务器面板、
6 面板统一检索、浮动窗口与命令面板、备份轮转与 schema 迁移、崩溃上报。

**对比 [FireAxe](https://github.com/ktxiaok/FireAxe)**：这是一套不同路线的工具（C#/Avalonia、**符号链接 push** 到游戏目录、
单存档 `.addonroot`、引用型节点）。本项目按 Apache-2.0 只借鉴设计与算法、用 Go / 原生 JS 重写，
优先保证"直接管理真实文件"：

| 维度 | FireAxe | 本 Fork |
| --- | --- | --- |
| 文件模型 | 库目录 + 符号链接 push（两套真相） | **直接管理真实文件**，改动立刻生效 |
| `addonlist.txt` | 重新写成 UTF-8 | 保持**原编码 / BOM / 换行**，原子写 + 事务回滚 |
| 备份 | 备份自己的 `.addonroot` | 多类型备份 + **运行时监控恢复** |
| 冲突结论 | "同优先级即冲突" | **严重程度分级** + 可组合基线 + 忽略清单并集 |
| 策略组 | 只能"应用策略" | 按组筛选、整组权重平移、分组推导与外部智能体导入、组内检索、展开成员直接操作 |
| 搜索 | 一套搜索选项 | **6 个面板统一语法** + 语法说明书 + 键盘光标 + 命中高亮 |
| 界面 | 固定布局 | 浮动窗口 + 命令面板 + 快捷键总览 + 字号/对比度/缩放 |
| 工坊链路 | 依赖 Steam 客户端回调 | 翻译 / 优选 IP / 分块下载 / 断点续传 / 转移 / 更新检测 / 合集实体化 |
| 附带工具 | 无 | 工具箱 8 件套 + **服务器面板**（地图 / 上传 / RCON / 难度 / 热重载） |

**已从 FireAxe 借鉴并落地**：优先级层级累加、同层冲突判定、忽略清单并集、备份轮转、组策略与可满足性预检、
push 事务化、存档 schema 版本化、下载暂停/续传/节流、Problem 自动修复分级、对象解释层（失败与灰按钮说人话）、
容器命名唯一、子问题上报父节点、树拖放、游戏目录探测、路径守卫、失效引用守卫、File Cleaner 冗余副本、
`F2`/`Delete`/`Ctrl+X`·`Ctrl+V`、主窗口几何记忆、剪贴板链接识别、自定义外部打开程序。
**有意不采纳**：符号链接 push、`RefAddonNode`、把优先级做成平行于 `addonlist` 的第二套状态、
就地按作品标题批量改名、猜文件名式修复、空目录清理（理由写在对照表里）。

**整合点（1+1>2）**：组权重 → 有效分层 → 冲突判定 → 列表排序 → `addonlist.txt` 一条链；
标签 × 分组建议互补（标签已覆盖的类型不必再建组）；分组建议 × 智能体材料 × 提示词编辑；
体检 × 依赖 × 事务写盘；统一检索 × 6 面板；备份轮转 × schema 迁移；浮动窗口 × 命令面板 × 快捷键。
完整对照（含 FireAxe 源码文件行号）见 [为什么用这个 Fork](./docs/guide/why-this-fork.md)。

## ✨ 本 Fork 新增与强化（相对上游）

> 清单最后更新：2026-09-27（`2.5.14-community.66`）。逐项用法与截图级入口说明见
> [新增功能一览](./docs/guide/whats-new.md)。

### `addonlist.txt` 全生命周期管理

- 根据目录类型准确定位配置：真实游戏 `left4dead2/addons` 使用游戏侧的 `left4dead2/addonlist.txt`；独立 Mod 收藏目录使用该目录自己的 `addonlist.txt`。
- 支持受保护快照、手动备份、恢复和删除；恢复或删除前会先保留当前配置，降低误操作丢失开关状态的风险。
- 可启用运行时保护：稳定检测到外部程序覆盖或删除配置后，先保存外部版本，再原子恢复受保护快照并同步游戏内开关状态。
- 可在写入前对比另一个 `addonlist.txt` 的新增项和开关冲突；冲突项默认保留当前状态，也可逐项选择采用来源状态。

### 可预览、可约束的加载顺序

- 加载顺序支持根目录与 Workshop 分组、完整顺序预览，以及明确的“必须在前 / 必须在后”约束。
- 应用策略前会校验约束并拒绝循环依赖；写入时原子更新 `addonlist.txt`，同时同步受保护快照。

### Workshop 安全标签与归档级内容识别

- 为 VPK 建立归档路径索引，无须把整个包解压即可基于真实内部路径分析内容。
- Workshop 中以纯数字发布 ID 命名的 VPK 不再被重命名；人工标签保存在同名 `.meta` 伴随文件，避免 Steam 或游戏失去识别。
- 扩展为适合 Workshop 大型库的细粒度标签：UI、声音、脚本、模型、贴图、物品、投掷物，以及角色、武器、地图模式等分类。
- 混合内容包仍保留稳定的主分类优先级（地图 → 人物 → 武器），并追加高置信度细分类，便于交叉筛选；规则回归测试覆盖常见名称误匹配。

### 面向大型 Mod 库的状态可视化与筛选

- 列表行和卡片使用颜色、徽标直观区分“游戏内开启 / 关闭 / 未记录”，并可直接按该状态筛选。
- 支持游戏状态、所在位置、一级标签与二级标签的组合筛选；文件处于 `disabled` 目录时会阻止不安全的游戏内开关编辑。
- 提供“集合 → 分类 → 具体物品”的多级预设筛选，覆盖枪械、官方近战、投掷物、医疗物品和补给盒；支持“任一匹配 / 全部匹配”且刷新后保留选择。
- 小窗口（约 1366px 宽）会收紧列和操作按钮，减少筛选与列表内容被裁切的情况。

### 分析、稳定性与 Fork 发布保障

- 扫描时将根目录与 Workshop 中的同名 VPK 作为独立条目处理，避免不同位置的 Mod 相互覆盖。
- 增加单实例启动辅助逻辑，减少重复启动产生的并发管理风险。
- 应用内更新源固定为本 Fork 的 `zombrain69/lytvpk` Release，拒绝回退到上游；Windows 更新包使用统一程序名并进行内容校验。
- 发布版本会附带对应源码、许可证和修改说明，便于用户核对并按 GPLv3 重新构建。

（模型面数统计已归到上面的「工具箱」一节：按需解析，不让普通目录扫描为每个 VPK 解析几何数据。）

### 统一优先级模型（分层 + 组权重）

- 显式**优先级分层**：在「加载顺序」窗口给单个或一批 Mod 设分层值（越小越先加载），点「按分层应用」才会重排；
  只有这时才允许重排，未设置分层时写盘内容与以前**逐字节一致**（有黄金回归测试守着）。
- **组权重叠加**：策略组的权重沿祖先链累加、跨链取 `min`，与单 Mod 分层合成同一个"有效分层"。
- **一份分级、三处共用**：列表排序、冲突判定、写回 `addonlist.txt` 用的是同一套有效分层，不会出现"看到一套、判成另一套"。
- **事务化写盘**：整批算完再落盘，中途失败回滚到写前的一致状态。

### 策略组与分组建议

- **策略组**：工具栏「全部分组」→ 建组 / 策略组管理窗口；组内策略支持 全部开启 / 全部关闭 / 互斥单选 / 随机单选，
  应用前做**可满足性预检**（空组、成员全丢等直接拦下并说明原因）。
- **层级与拖放**：支持「＋ 子组」「上级分组」下拉，也可以直接把组拖进另一组、拖到前面后面或拖回顶层（拒绝成环、最多 4 层）。
- **批量管理**：多选组后批量删除 / 开关自动联动 / 设置或清除权重 / 用选中的组筛选主列表。
- **展开成员即可操作**：展开后能看详情、改游戏内开关、启用禁用、复制到 addons、把单个 Mod 移出本组。
- **分组建议**：内置规则（工坊合集、文件名前缀、共同标签、作者、主体、换装/动作槽位）推导可能同组的 Mod；
  还可以「准备给智能体的材料」导出最新清单 + 提示词，交给大模型分析后把标准建议文件**导回**应用逐条采纳。

### 冲突分析、忽略清单与自动复检

- **每 Mod 冲突忽略文件**：内置规则 ∪ 全局清单 ∪ 单 Mod 清单取并集；单 Mod 清单在「详情」里直接编辑。
- **同层才算真冲突**：同一有效分层内判为冲突，其余按覆盖关系展示；保留既有的严重程度分级与可组合基线。
- **变更驱动复检**：开关、启用、改名等状态变化后自动让相关结果失效并按需重算，列表角标同步更新。
- **冲突弹窗可检索**：与 Mod 列表共用同一套搜索语法，大库也能快速定位到某一组覆盖关系。

### Mod 体检与一键修复

- 设置 → 游戏配置 → **Mod 体检**：重复条目 / 缺失条目 / **依赖未开启**这几类可一键修复（写前自动备份，走 `addonlist.txt` 事务）。
- 新增诊断：工坊作品重复副本、文件类型不符（同名文件夹占位）、工坊记录 ID 不一致、条目落在受管目录之外、依赖成环。
- 报告支持统一检索与导出 Markdown，便于留档或发给人看。

### 启用方案与 Mod 依赖

- **启用方案**：把"哪些开 / 哪些关 + 分层"存成方案，一键切回；支持捕获（含自动化信息）、应用、导出、导入。
- **Mod 依赖**：声明"开 A 必须先开 B"，体检报出并可一键启用依赖；依赖成环会被检测并写出完整链路。

### 工坊链路（官方标签 / 合集 / 翻译 / 剪贴板识别）

- **官方标签与统计**：设置 → 工坊设置 → 「抓取工坊官方标签与统计」，走 Steam 官方
  `GetPublishedFileDetails`，把作者填的分类（如 `Survivors` / `Sounds`）与订阅、收藏、浏览写进 `.meta`；
  抓过之后「准备给智能体的材料」会多出 `steamTags`，分组建议更准。
- **工坊合集**：设置 → 工坊设置的「工坊合集」卡片支持抓取合集、刷新成员、补下缺失、检查更新。
- **描述翻译**：内置多种翻译服务，也可填自己的接口（设置 → 工坊设置 → 描述翻译）。
- **剪贴板识别**：复制工坊链接（或纯作品 ID）后切回应用会问是否直接解析；窗口不在前台时不读剪贴板，同一条不重复提示。

### 下载（暂停 / 断点续传 / 自动重下）

- **暂停与续传**：任务列表里可暂停 / 继续，按**区块检查点**续传；暂停、失败、重启后都能接着下。
- **进度落盘节流**：进度快照按 1 秒节流写盘，内容相同不重复写；重启后未完成任务显示为「已中断」并可一键重试。
- **自动重下**（默认关闭）：设置 → 工坊设置开启后，新任务失败自动重试一次；任务行也能单独开关。
- **优选 IP**：设置 → 网络设置；下载链接含 `cdn.steamusercontent.com` 时可临时勾选。

### 工具箱（8 件套）

左侧导航 **工具箱**：问题 Mod 查找（二分法）、Mod 冲突检测、模型面数检测（LOD0 顶点 / 三角面）、
崩溃转储查看器（`.mdmp`）、喷漆制作、autoexec.cfg 编辑器（识别命令含义 / 风险 / 来源，保留原编码与换行）、
VPK 解包与打包、VPK 完整性检测（可安全修复并另存）、压缩包管理（ZIP / RAR / 7Z / TAR 里识别 VPK 并与现有 Mod 对比）。

### 收藏服务器与服务器面板

左侧导航 **收藏服务器**：A2S 查询状态与玩家、收藏 / 最近列表；在服务器详情里打开**服务器面板**，
可以改难度、管理地图、上传地图文件、发送 RCON 指令、热重载地图，并跟踪上传任务进度。

### 检索体验（6 个面板同一套语法）

- Mod 列表、冲突弹窗、体检结果、归档管理、模型统计、策略组管理共用一套搜索语法：
  多词"且"匹配、`-词` 排除、`tag:武器|角色` 按标签、`re:^ak` 正则、`"精确短语"`。
- 结果支持 `↑` `↓` 移动键盘光标、`Enter` 打开详情、`Esc` 清空；`?` 打开语法说明书（与快捷键总览同源）。
- 创意工坊浏览器的搜索是**服务端搜索**，只支持关键词（界面里已写明）。

### 界面、窗口与快捷键

- **阅读舒适度**：界面缩放（80%–140%）、文字大小四档、对比度三档，都对硬编码字号做过统一治理，全界面生效。
- **浮动窗口**：复杂管理窗口都能浮动 / 拖动 / 拉伸 / 点外部关闭，背景不虚化；跑飞时双击标题栏复位，
  或用命令面板的「重置所有窗口的位置与大小」。
- **窗口尺寸记忆**：主窗口宽高与最大化状态写入 `config.json`，下次启动恢复（换小屏会先按屏幕钳制）。
- **命令面板**（`Ctrl + K`）：搜页面 / 功能 / 动作，记住最近使用；**快捷键总览**按 `?`。
- **编辑快捷键**：`F2` 重命名、`Delete` 删除（多选走批量）、`Ctrl + X` 标记待移动 + `Ctrl + V` 选目标目录移动。
- **自定义外部打开程序**：设置 → 界面设置 → 「打开文件方式（可选）」填程序与参数模板
  （`{path}` / `{dir}` / `{name}`，留空 = 系统默认）。

### 数据安全与稳定性

- **本地记录备份轮转**：`profiles.json` / `groups.json` / `dependencies.json` / `ignore.json` / `priority.json`
  都有最短间隔、内容相同跳过、数量上限与回收站溢出；文件带 `schemaVersion`，旧结构自动迁移，坏值读时修正。
- **路径守卫**：删除 / 移动 / 改名的**源文件**必须在 addons / workshop / disabled 之内（"移动到用户自选目录"仍然允许）。
- **文件操作互斥**：移动 / 删除 / 打包同一时间只允许一个，忙碌状态显示在界面上；
  批量操作的失败原因逐项列出（前 3 条 + "另有 N 条"，控制台保留全量）。
- **失效目标守卫**：下载检测等后台任务在写回前复查目标是否还在，被移动 / 替换就不写。
- **崩溃上报**：自身崩溃会在「关于」页给出报告（版本 + 日志尾部），与工具箱的 `.mdmp` 查看器互补。
- **游戏目录自动探测**：注册表 → `libraryfolders.vdf` → 盘符兜底，自定义 Steam 库也能找到。

## 🛠️ 技术架构

### 后端 (Go)
- **框架**: Wails v2
- **VPK解析**: 使用 `l4d2-manager-next/pkg/valve/vpk` 和 `l4d2-manager-next/pkg/vpkmission`
- **并发处理**: `github.com/panjf2000/ants/v2` 协程池
- **配置管理**: JSON 格式的持久化配置

### 前端 (JavaScript + CSS)
- **原生 JavaScript**: 无框架依赖，轻量高效
- **现代 CSS**: 基于 CSS 变量的设计系统
- **响应式设计**: 支持桌面端和移动端
- **实时通信**: 通过 Wails 事件系统与后端通信
